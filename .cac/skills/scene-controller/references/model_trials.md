# 候选模型试验与交付

## 运行边界

模型顺序、实际端点、推理控制、各阶段输出额度、全局并发、筛选增量预算和原模型账本均由运行配置提供。先预检候选及固定独立审查员；记录请求模型、服务返回模型、版本依据和结构化输出能力。未发送思考参数不代表已关闭思考。无权限、429、断连、未知用量和额度停止分别记录，不算语义能力失败。

先在固定的合法上游输入下筛选阶段能力，再让合格候选独立构建完整用例。难例涵盖正常抽取、图/参与者、特性、G/E/T、规范化、逆向审查、比较和定向修复。固定上游难例通过不代表该候选能从原始材料独立完成全流程；含其他模型修复上下文的试件须单列。

## 独立与辅助

独立试验禁用跨模型 fallback 和语义 supervisor。宿主主控可修复通用工具并离线复验原返回，但不能把自己补写的内容记成候选输出。正常/G仅用正向来源，E和T各自独立；历史异常仅进入推荐通道。

每阶段最多使用约定的定向自修复轮次，续跑累计计数。筛选增量预算计入同一模型原账本；成功结果必须完整核对输入、指令、契约、请求身份和执行证明，不能仅凭 input 字段或 passed 标签复用旧筛选。

独立失败后，先固定失败结果和阶段，再显式进入主控辅助模式。保留成功包，真实记录由谁补全及额外用量；辅助交付通过不能更改候选独立失败结论。相同失败无新的诊断或工具修正时禁止盲目重投。

## 验收与报告

固定独立审查员作为外部裁判，不代写候选结果。正式交付仍要求完整任务、当前校验器、回归、零新增模型调用续跑、实际独立审查及快照重建全部通过。找到首个符合用户口径的候选后停止新增完整实验。

报告分开列出首次完成、自修复完成、主控辅助、权限/传输/预算停止；按阶段统计请求、实际输入输出用量、修复成本、API时间、墙钟和缓存。未知用量保持未知。总参数和激活参数只引用对应版本的公开依据，不从 Flash 名称或单个用例推断通用最低参数量。

主控等待由本地执行器或事件通知承担，只在推进、失败或需要决策时调用主控；不得用付费模型持续轮询。实验结果保留本地，Git文档只描述通用方法。
