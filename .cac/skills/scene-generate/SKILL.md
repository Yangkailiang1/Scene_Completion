# 场景生成

逻辑查询返回可带 `derived_response_data`，表示原文正向查询的语义对象、协议结构待确认。生成时保留此推导标记及真实 SSD 返回锚点；它不能证明 JSON 成员、类型、必填、长度、范围等接口限制。未知限制保持待确认，不用逻辑标签编造契约；不通过原文异常或测试条件補写生成场景。

五类功能服务关注点在SR真实服务上按正向操作特征挂载；RR以原文正常业务职责建立逻辑业务服务角色，绑定本层真实SSD交互及对应SR展开。角色不是新增部署组件，不将SR生成异常复制成RR异常。RR/SR分别独立生成、同层一一匹配并验收。

同时读取 RR 和 SR spec，IR 是 RR 的别名。测试 spec、检查器集合及历史候选不得作为生成输入。
先抽取正常与普通可选流程及逐层对应关系，再建立架构、融合 SSD 和关注点挂载。
正常与可选流程保留导出，但不参与异常评估和推荐。

RR 分析人类与 UI、外部调用方与逻辑接收边界；SR 分析边界到明确 SR 接口，以及有依据的 SR 服务间交互。
一条 RR 业务动作可以展开多条 SR 交互，保留分支、顺序、请求/返回字段及逐层返回。
用例分解独立于消息嵌套：一个 RR 可拆多个 SR，每个 SR 可拆多个 AR，每个 AR 可对应多个软件实现接口。候选保存所属拆分单元，不能把所有 SR 归到一个默认接口，也不能由样例编号推断一一对应。
AR 实现微服务只作为融合图追溯，不参与异常生成，不把 AR 微服务提升为 SR 来获取覆盖。
内外数据库均包装为 SR 资源服务，并在实际 SSD 生命线、消息端点及架构图中体现；保留物理映射，不虚构部署或接口路径。

原文约束只能写入已经绑定的交互契约：字段、合法状态、权限归属、资源依赖、金额、幂等键、版本和时间规则。
禁止直接追加原文明示异常，禁止独立 generation_constraints 生成路径，禁止生成后再补贴 SSD 锚点。
异常唯一生成链为：真实交互 → 关注点挂载 → 当轮授权模型具体化异常对象、操作位置、失败机制和触发条件。批量模型由配置、环境变量或 --agent-model 选择，可使用 当前配置的语义模型、其他可用模型 等兼容API或配置的原生子进程模型。最终独立效果审查仍使用既定 配置指定的独立审查模型，实际模型及推理设置分别记录，不能改写历史执行身份。
每个有效挂载必须保留候选，不进行 LLM 适用性筛选或删除；未知数值限制、响应和恢复明确标记待确认。
没有有效同层 SSD 交换/消息/挂载时记录模型缺口，阻止正式验收，不使用其他生成路径补齐。

生成前必须通过tools的正常模型来源与完整性检查：`model_origin_checks.json`及完整当前版本的`interaction-model-audit`。逐原始正常步骤、已建交互和普通可选场景核实，不允许漏掉有依据的SR资源服务操作、不将返回建成请求、不将正确处理的异常算普通可选。该审查只输入原文与正常模型，不输入C/G/测试，也不对异常候选进行适用性审查。模型缺口从原文重抽并保留原始反馈，不能手写异常修补。每轮提供`check-interaction-run`生成的`run_checks.json/md`；结构完整、全部批次完成和正式验收分开报告。

迁移到新项目必须重新定位原始RR/SR用例与层级关系，用有证据的交互特征路由全部关注点；禁止在Skill或tools中加入样例专用服务名、用例前缀、异常条件、固定分母或预期匹配关系来保证指标。测试应覆盖不同项目编号和数据对象的同一方法约束，样例达标不能代替方法检查。

RR、SR 分别挂载与生成，不复制异常结果到另一层。不同对象、机制和时间参照点分别记录。
正常交互先提取有原文依据的 operation_kinds 和 data_relations，tools 据此确定性挂载；保留全部关注点注册，不要求每条交互无条件挂上所有类别。只读交互不生成未建模写入、缓存回填、统计更新、事务回滚或联查。只有本交换有写操作或明确关联/唯一键契约时，才挂对应写入、级联或唯一性关注点；这属于交互特征路由，不作 LLM 适用性审查。
每条候选只描述一个对象/字段与一种失败机制。多个独立字段分别具体化，不用“其中任一字段缺失”代替逐字段候选，也不同时保留集合 OR 与成员候选。未知字段必填性、类型、格式、长度限制只写条件性候选和待确认，不宣称原文已规定；已明确可选的字段不变成必填。
RR 中点击、选择等业务交互保持 RR 词汇，不冒充 HTTP 请求体或搬用 SR 参数。异常识别字段只能描述本 SSD 实际操作及其潜在失败条件；未知的拒绝、回滚、崩溃、恢复或内部实现不能写成确定机制或必要条件。pending_details 不能抵消识别字段中虚构的操作。
异常路径不能包含取消/失败之后互斥的成功步骤。响应、错误码、恢复不参与异常识别覆盖判定。

必须保留用户规定的人、外部服务/数据库/LLM、五类内部服务、内部依赖、七类数据和十类内部数据库关注点。
设备适配性与其余展示关注点同为有效基线。内部服务依赖图需保留有证据的实际调用和挂载。
有匹配漏报时分析架构、交互、挂载、具体化或匹配错误；不能读取漏报条件直接回填 G。
其他组件、调用边、关注点增删须先给出原文依据、图上位置及影响请用户确认；边界与数据库服务化已授权。

新协议见 ../scene-check/references/rr_sr_protocol.md。references/legacy_v1.md 仅用于重建旧实验，不能作为本轮验收方法。

生成前执行scene-participants：对照原始架构与用例Actor/参与者声明，已有正常调用但Actor漏写时补全模型参与者并保存依据；只有架构服务、没有本用例调用证据时列待确认，不造调用。文档编辑或新增调用仍先确认。可取消属性仅保留正常可选能力，不自动挂遗产业务流程中断异常。
