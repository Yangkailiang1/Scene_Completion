# RR/SR 异常识别协议

当前用户确认（2026-10-11后续修订）：RR建立有本层正常依据和真实SR映射的五类逻辑业务服务职责，RR/SR分别生成、同层一一匹配。漏报率≤5%门槛已撤销，只验证可迁移方法流程；指标如实报告。全部推荐沿RR/SR映射按同一因果关注点语义去重；测试独立按交互关注点拆分，允许框架推导原因但明确标记，再一一匹配。原文覆盖和采纳均不允许多对多计数。主动取消是普通可选，可取消属性不自动挂异常。当前机器规则rr-sr-one-to-one-workflow-v5；之前的阈值及仅SR范围保留为历史，不用于新验收。

版本：rr-sr-ssd-identification-v1。历史生成、37 条分母和零漏报结果仅为旧协议记录。

1. 独立生成输入读取 RR、SR，正常/可选流程→架构→融合 SSD→全部有效关注点挂载→ecnu-max 异常具体化。
2. 独立检查输入分别读取原始 RR、SR，冻结各层原子异常集合。抽取不读取 G/测试。
   用户确认泛指异常分支可结合同操作明确契约展开，纯前置条件不算；保存 extraction_basis、异常分支及契约引用。字段/机制分别原子化，入口字段与下游转换字段不能混淆。
   工具校验两种引用属于实际层级用例；独立接口章节必须以 operation_binding 引用本用例原文明示正常调用，并验证契约归属该接口，不能借用同业务包其他 SR 的规则。
3. 同层同原文层级用例逐对比较识别条件，不比较响应/恢复。每个必要条件保留证据或明确缺口，不同 SR 单元不能互相代替。完整与部分计重合，所有未完成批次阻止指标。
4. 各层及合计：漏报率=未覆盖唯一 C/全部 C；完整率=已匹配唯一 G 异常/全部 G 异常。
5. 分类识别漏报按 C 分类统计；标签差异及同类挂载覆盖另列。多关注点不能相加得到总数。
6. 推荐仅未分配G异常，全部显示原成员和评分；按真实RR/SR映射及同一实际原因语义去重（保留不同层关注点标签）。测试不分层、不按用例编号排除比较，独立拆分明示/框架推导交互关注点单元；全部逐对判断后一一分配。采纳率=已分配推荐单元/全部推荐单元，零分母null，无额外门槛。
7. RR、SR漏报率、完整率及分类指标如实报告，空分母null，不设置覆盖达标阈值。原文覆盖一一分配，合计报告。完整回归、独立复核、同版本续跑、离线重建及实际Luna效果审查后交付方法流程。
8. C 冻结前须完成只读原文/C 的 interaction-checker-audit，记录原文支持、原子性、操作归属、引用和遗漏。有问题的草稿保留原始结果和完整依据，用 repair-checker-source-audit 从原包重抽再全量审查；冻结基线不原地改写。每轮 tools 自动输出 run_checks.json/md，check-interaction-run 可核查未完成状态与显式原文版本。

关注点基线由 tools 的 interaction_protocol.baseline 输出；设备适配性、五项 LLM 质量均有效。
每个交换的 operation_kinds 和有原文依据的 data_relations 决定确定性路由，全部57项注册保留；只读交互不继承写类关注点或未证实的副作用。未知实现细节不能进入异常识别字段，RR业务交互不能冒称HTTP请求体。不作LLM适用性筛选，保留每个有效挂载的全部具体候选。
内部/外部数据库实际包装为 SR 资源服务。其他组件、调用边或关注点新增先经用户确认；漏报不得回填为生成输入。
关系提取必须保存表达其类型的原文 evidence_quote，不凭 ID 推断唯一键或外键。SR 身份按 UI/接收边界区分人类和外部调用方；LLM 访问本系统权限只挂入站方向，调用模型的响应挂五项质量、可用性与契约。
正式验证由 validate-interaction-run 保存实际 pytest/JUnit 日志、禁用模型调用的全批次缓存续跑以及前后集合/指标哈希。prepare-interaction-review 保存具体结果材料版本；实际 Luna 审查原始结论逐项覆盖 SSD 唯一路径、层级、全部关注点、原文原子性、识别量表、指标分母、推荐去重、测试拆分及一一采纳。evaluate-generator 核对所有证据而非 passed 布尔值。固定 C 的核实记录还须绑定 source_audit_hash，防止审查证明漂移。
