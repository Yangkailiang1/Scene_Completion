# Scenario Match

默认执行 RR/SR 异常识别协议。只比较异常对象、操作、失败机制和必要触发条件；响应、错误码、处理和恢复不影响覆盖。正常与普通可选场景不参与比较。

每包一个 C、最多八个同层同原文层级用例的 G 异常，所有比较对完整返回。不得用字符串相似度、共同主题、关注点名称或普通操作相同替代异常条件识别。不同对象、机制或矛盾条件必须 unmatched。

full 识别同一具体异常且条件充分一致。partial 必须识别同一具体异常，逐项指出 C 中未识别的条件细节，并引用实际条件；缺少响应或恢复不能构成 partial。按合同返回对象、操作、机制、触发条件的双端精确依据，以及每个必要条件的 supported/missing/contradictory 判定。

完整、部分均可作为一一匹配的候选关系；工具在完整逐对语义判断后选择最大配对数、再优先完整匹配的确定性一一分配。每个C和G只能占用一条计数关系，未分配的语义重合另列，不能多对多计覆盖。分类差异单列，不作为异常漏报。未完成或过期包阻止正式指标。第二次独立比较覆盖所有对，逐项核对对象/操作/机制断言、必要条件关系及缺失条件原文集合，不能仅因状态同为partial认为一致。条件支持必须引用G的完整触发条件、失败机制或单个必要条件并说明对应关系，不能用“读取”等泛化操作词片段充当具体条件。

系统spec与设计spec的异常分别匹配，各自保留原文层级和完整分母，不跨层混算。测试spec不区分RR/SR：interaction-adoption专用test_all范围将全部待推荐异常与全部独立测试异常条件逐对比较，不按层级或用例编号筛掉比较对。标识仍供核对具体业务上下文；不同对象、操作、机制或矛盾条件必须判未匹配，普通正常操作相同不计。

推荐采纳率=一一匹配到测试异常单元的推荐单元数/全部推荐单元数。真实RR↔SR映射下同一交互关注点的相同具体异常先语义去重，原成员与证据全部保留；不同原因或关注点单元不合并。测试不分RR/SR，按交互、单一因果关注点、具体条件拆分；用户允许展开可能原因，必须标为framework_derived并保留原文与推导依据。普通正常条目仍不能展开异常。测试采用test_all完整比较后进行一一分配，零分母null。系统/设计仍分开同层匹配；RR、SR指标仅报告，不设漏报率通过阈值。

旧 score-scenario-matches 命令的 full-only 测试代理指标仅为历史兼容，字段见 references/matching.md；不能用旧全 G 比例替代本协议全部待推荐异常的采纳率。本 Skill 不调用其他 Skill。

用户进一步确认：同一实际原因跨RR/SR只有关注点编码/分析视角不同，仍合并一个推荐因果单元并保留全部原始关注点标签；不同实际原因才拆分。测试每个拆分单元有一个因果关注点，匹配按具体原因，不能以标签相等替代机制判断，也不能仅因标签不同拒绝同一原因。
