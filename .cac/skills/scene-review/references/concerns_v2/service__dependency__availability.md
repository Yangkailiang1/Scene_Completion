# 内部依赖可用性

检查有原文证据的内部业务服务调用失败、连接失败或不可用。挂载到真实调用边及被调用
服务，保持 SR 检查位置与 AR 实现证据关联。数据库访问使用数据库关注点；第三方支付、
物流等边界外服务使用 external_service.availability；单纯参数错误不属于此关注点。

从实际调用与正常可用性条件产生具体失败候选，记录调用对象、操作、步骤、影响及来源。
未给定的错误响应、超时阈值与重试次数使用待需求确认。不得为了产生候选补造内部调用。

正例：订单服务调用商品目录服务校验库存时，目录服务不可用。
反例：顾客提交不存在的商品ID，应检查资源存在性而非服务不可用。
