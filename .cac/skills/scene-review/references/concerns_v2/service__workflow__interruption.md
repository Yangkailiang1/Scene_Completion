# 业务流程取消与中止

此项属于历史审查兼容功能，不属于当前 RR/SR 异常生成注册表。用户主动取消支付是普通可选场景，不能计入检查器异常分母，不能因可取消属性自动挂载异常；下列历史检查例只讨论可选流程路径与副作用，不证明取消本身是异常。

检查参与者取消或中止已开始的业务流程时，业务状态及已发生副作用是否得到文档规定的处理。
挂载到具体流程状态或取消交互；与服务故障、请求格式错误和重复请求分别检查。

只有原文描述可取消/中止事件或正常流程明确存在相关状态时才具体化此候选。记录取消
发生点、涉及状态、实际分支路径及来源。不得保留取消之后的支付成功等互斥成功步骤。
未规定的退款、补偿、清理与最终状态标记待需求确认，不虚构执行能力或新组件。

正例：顾客取消订单支付，订单仍保持 WAIT_PAY。
反例：支付服务连接失败，属于调用可用性问题。
