# 模式适用性与场景实例化

只读取本用例正向交互、实际操作、接口约束、正常规则、关注点及项目模式快照。禁止读取E、GT、M、推荐和测试异常答案。

1. 按本次实际操作及技术特性筛选模式；请求和返回分开。
2. 工具按结构化约束构造独立违例，上界和下界分别计数，重复测试值不新增场景。可选缺省正常。
   同一交互的数据序列和接收方API要求取有据并集；同名同位置合并，来源保留，不检查需求一致性。数据类型、格式、文件大小和数组数量不能相互替代。已识别的大小关注点有大小校验依据但未说明方向时，展开低于下界、超过上界两条条件级场景；明确单边时仅该边。未知数值保持未知、不可直接执行，不用示例补写本用例的要求或GT。
3. 认证/授权子模式需各自的正向前提，不能从“需认证”推断存在撤销机制或跨租户边界。
4. 工具分级：结构化约束1、完整业务规则0.85、框架提示但前提不足0.6、明确不适用0。分数是依据充分性，不是概率。
5. 一个失败关联多个关注点仅保留一条实例；保留模式ID、关联关注点、具体交互、字段、独立条件、来源、风险、可执行性及版本。
6. 达项目阈值且适用的实例进入G；关键低置信进入待审，不进入G/Q。显式格式规则但未知标准可保留条件级，不补造阈值、响应码或恢复行为。

输出为pattern-applicability.json及可审阅Markdown；结果按项目和版本冻结。此步骤为确定性工具，不为已知字段重复调用模型。

## 关注点先于场景
只能为concern-match中已识别且applicable的具体关注点生成场景；不可从注册表补入漏识别项。一个独立失败条件计一条，上下界拆开，多个违例数值不重复计数。保留四要素对象与关注点绑定ID。同一失败关联多个关注点只计一次。
