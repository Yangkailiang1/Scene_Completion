# 异常分析粒度分流
输入channel为existing或test；source-records是各自异常原始记录，禁止读取G或比较结果。逐原记录保留source_id，每项至少输出一个unit，不确定填pending。
只将实际失败触发分类。预期结果“不重复业务变更”“回滚成功”“返回状态码”本身不构成幂等/恢复失败。普通正常重放不造异常。同键不同内容未拒绝、重复执行产生额外业务影响属于全局idempotency；商品已发布、新键再次发布的状态限制属于交互级业务前置条件，不因出现幂等键就判为幂等。
交互级：一次具体调用/返回/自检上的数据、认证授权、外部可用性、存在性或独立业务约束等。全局级：用例/业务实体间明确调用顺序sequence、依赖一致性dependency_consistency、级联cascade，及业务操作重复执行的idempotency。跨服务数据一致性仍为交互级。
混合记录可以输出多个独立trigger，但同一失败只输出一次。不要将整条预期响应再拆成异常。401/403等编号不能替代触发条件；认证与权限分别分类，不把相邻原分支自动复制进本分支。
全局unit填写相关业务实体稳定ID及用例组ID；没有足够依据不能猜依赖关系。interaction或pending的global_kind必须null。reason说明归属依据，trigger保留独立失败必要条件，不包含正常成功或处理断言。
相关用例及实体的顺序表示依赖方向：前置/被依赖方在前，后续/依赖方在后。不能只因两个用例都操作Product就构造依赖；未知方向填pending。单个用例中的本地状态校验、字段校验仍为interaction，不因涉及业务实体就升为global。
