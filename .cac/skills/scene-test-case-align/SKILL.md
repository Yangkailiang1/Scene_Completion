# 测试与需求用例对应

输入：test-inventory、rr-cases、sr-cases、case-groups。仅含测试自身描述及RR/SR用例的名称、目标、参与者和原文依据；不读取G、E、GT场景、覆盖匹配、推荐或指标。

首先使用明示需求编号；编号不同则比较业务目标、参与者、操作对象及接口线索。名称不必字面相等，例如测试侧恢复编号不能仅因不同就被丢弃。不得依据当前算法是否命中测试来选对应关系。

每个测试用例必须输出一条对应：confirmed时引用真实case_group_id；无法确定时pending，无对应时unmatched，二者group ID为null并说明原因。一个测试用例存在多个业务目标时先在测试整理阶段分清场景归属，不强行绑定到一个无关用例。保留测试原编号及双侧依据。

这里只对齐用例，不把整个用例当作某个实际交互。后续test-concerns再依据融合SSD定位发送方/接收方/操作项/数据实体及具体关注点，再进行GT场景细化。
