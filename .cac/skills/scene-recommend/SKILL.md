# 场景推荐

只接收每层未匹配 C 的 G 异常。正常、可选及部分匹配不进入推荐集合。
Agent 或 embedding 后端均保留全量候选、支持度、缺失度、加权分数及依据。
标注为推荐评分，不是校准概率；相关主题不能自动证明异常合理。
支持度评价 SSD、交互对象/数据、契约对具体异常条件的支持；缺少响应或恢复不扣识别支持度。
评分为 0.7×支持度+0.3×缺失度；保存原始分项、理由、SSD 位置、证据与建议补充章节。

可用 rerank 对 embedding 召回的最多 20 段需求/设计证据精排。
仅增强推荐，不改变候选和指标；失败时停在未完成状态，不隐式替换后端。
分别给出证据章节和建议补充章节，无法定位时明确说明。

测试 spec 仅用于独立验收，测试不按RR/SR分区：推荐先沿真实RR/SR映射按异常对象、操作、机制、必要条件及因果关注点做语义去重，原成员全部保留。测试按交互关注点拆分成原文明示/框架推导单元；逐对完整判断后一一分配，采纳率=已分配推荐单元数/全部推荐单元数，不按RR/SR或用例编号筛掉测试比较对。框架推导贡献明确单列，不冒充原文测试已写明的原因。
可选测试条目中的异常条件允许重合，普通正常流程不能凭操作相同匹配；不同业务对象、操作、机制或矛盾条件判未匹配。推荐为空返回null，不设未经约定的采纳率门槛。
新协议见 ../scene-check/references/rr_sr_protocol.md。

用户进一步确认：同一实际原因跨RR/SR只有关注点编码/分析视角不同，仍合并一个推荐因果单元并保留全部原始关注点标签；不同实际原因才拆分。测试每个拆分单元有一个因果关注点，匹配按具体原因，不能以标签相等替代机制判断，也不能仅因标签不同拒绝同一原因。
