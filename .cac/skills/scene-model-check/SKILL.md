# SSD与系统组成检查

仅读取原始正常/普通可选流程、正向契约及抽取模型，不读取G、已有异常逆向结果或测试GT。SSD核实实际调用双方、RR→SR展开、请求顺序、请求/返回数据、逐层返回与来源；系统组成核实人类/外部服务/LLM、边界、SR服务职责及内外数据库资源服务映射。

逐项覆盖输入的全部交换和组件。已有锚点虚构、错层、循环或把本地校验写成自调用时拒绝，给出原文连续引句及引用。未抽取的流程/字段及未知契约作为独立完整性诊断保留，不能借检查造调用或改写业务材料。AR只在架构/实现追溯中存在，不成为RR/SR异常分析交互。

检查按实际用例、组件及来源版本保存。已证明的相同组件检查可复用，未通过组件只阻塞实际依赖它的用例。修复后执行原校验器和新语义检查；误判也须先保留原文复核依据，不改写既有通过标记。自动修复最多两轮，原文冲突或新增建模项进入待确认，预算及原执行记录续跑保留。

区分结构及真实锚点检查与输入完整性/质量发现；保留否定结论及警告，不手写通过或用响应状态倒推出异常。内部/外部物理数据库必须封装SR资源服务，未知接口路径待确认。
