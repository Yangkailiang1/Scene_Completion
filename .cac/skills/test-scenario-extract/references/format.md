# 参考测试规格格式

支持 Markdown 和 Excel（`.xlsx/.xlsm`）。Excel 每条测试占一行，表头包含：用例编号、用例名称、前提条件、测试步骤、预期结果、对应需求。允许多个测试工作表，保留工作表、行和单元格来源；公式须先转为明确值。旧 `.xls` 文件请先另存为 `.xlsx`。

Markdown 可使用同样六列表格，也可用三级标题 `### TEST-ID：用例名称`，标题下写 `- 前提条件：…`、`- 测试步骤：…`、`- 预期结果：…`、`- 对应需求：…`。步骤可多行或用 `<br>` 分隔。场景类型可选；未标注时为 `unspecified`，留给独立语义抽取判断，不将所有条目默认视为异常。示例见项目 `examples/test_spec.example.md` 和 `examples/test_spec.example.xlsx`。

兼容旧版七字段 Markdown：场景类型（正常/异常/可选）、前置条件、触发条件、关联需求（可含 AR/SR/API/Use Case ID）、测试目标、预期结果、来源定位。`###` 场景标题之间的正文归属于当前场景。

抽取 JSON 使用 `schema_version: 1.0` 和 `scenarios` 数组；保留原场景 ID、步骤、需求关联，并校验唯一性及必需字段。六字段格式中的步骤作为原样触发描述，名称作为目标，原始文件位置作为来源定位；不补写测试行为。
