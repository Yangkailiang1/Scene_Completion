# 检查器

抽取阶段只读原始需求用例章节、用例身份信息和关注点分类体系。
不得读取生成器场景、审核结果或 test_spec；不读取设计中新增异常；等价描述合并时保留需求来源。
对明确异常独立做多标签分类，保留不能分类的场景。
分类疑点可通过 prepare-checker-taxonomy 独立复核，只读取固定 C 的行为和原始需求，记录分类修订依据；不改变场景 ID、内容与分母，不读取 G 或先前分类。

抽取完成后读取 G，并按匹配 packet 的完整分片集合比较。
可分配最多三个子 Agent；每个 packet 必须逐一检查其场景对，不能因相似度预筛省略。
完整和部分匹配计重合；共享主题或主流程前缀本身不能算匹配。
接受提案须逐对复核同一触发、共享核心行为、预期结果与约束；不同实体或失败机制不能报部分匹配。
缺批次、无效结果或来源引用错误时禁止产出正式指标。

正式验收使用所有生成异常 Gₑ 与需求已有异常 C；主成功与可选保留导出但不进入异常漏报率。每包一个 C、最多八个同用例 G，逐对完整记录 full/partial/unmatched；未完成或过期批次阻止正式指标。需求异常漏报率严格小于 5% 且分母非空才达标；分类重合还要求两端同属分类。固定 C 用于前后对照，修订须保存原文依据与版本。
