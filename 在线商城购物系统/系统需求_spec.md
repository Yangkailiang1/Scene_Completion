# 需求[RR-DELTA-001]描述

> 本文档为仿真数据，所有名称、编号、接口和业务数据均为虚构。

## 价值

为顾客提供完整的在线购物能力，为商家提供商品发布与履约能力，并通过支付、物流服务完成交易闭环。

| --- | --- |
| RR | 系统需求编号 |
| UCG | 用例组 |
| UC | 用例 |
| SKU | 最小库存单位 |
| ProductBrowse | 商品浏览模块 |
| PaymentService | 第三方支付服务 |
| LogisticsService | 第三方物流服务 |

## 系统上下文

### 目标系统

| 系统名称 | 系统边界说明 |
| --- | --- |
| 在线商城购物系统 | 系统负责商品浏览、购物车、订单、商家商品管理、支付协调和物流信息展示；第三方支付扣款及实际物流运输不属于本系统边界。 |

# 场景用例分析

### 场景划分

#### UCG-001：商品浏览与选购用例组

顾客浏览商品、查看商品详情，并将选中的商品加入购物车。

#### UCG-002：订单处理用例组

顾客根据购物车创建订单、完成支付并查看订单详情。

#### UCG-003：商品管理与售后服务用例组

商家完成订单发货，顾客或外部服务更新、查询物流并处理退款。

#### UCG-004：商家上架用例组

商家创建商品、填写商品资料、设置库存与价格并发布商品。

## 用例详细说明

### UCG-001-UC001：浏览商品

1. Actor：顾客
2. 前置条件：
   ① 在线商城购物系统正常运行。
   ② 商品浏览功能和商品目录服务可用。
3. 后置条件（成功保证）：
   系统展示符合当前条件的可售商品列表。
4. 触发事件：
   顾客进入商品浏览页面，或发起商品搜索、筛选请求。
5. 主成功路径：
   ① 顾客进入商品浏览页面。
   ② 系统通过商品浏览接口 API-S-IF1 展示当前可浏览的商品列表。
   ③ 顾客输入关键词、选择分类或设置价格、排序条件。
   ④ 系统根据条件查询状态为 ON_SALE 的商品。
   ⑤ 系统展示符合条件的商品列表和分页信息。
6. 扩展路径：
   3.a 可选场景：顾客未设置搜索或筛选条件。
   → 系统按默认规则展示商品。
   4.a 异常场景：未查询到符合条件的商品。
   → 系统返回空列表并提示“暂无符合条件的商品”。
   4.b 异常场景：查询参数非法。
   → 系统提示顾客修正查询条件。
   4.c 异常场景：商品目录服务超时。
   → 系统提示“商品加载失败，请稍后重试”。

### UCG-001-UC002：查看商品详情

1. Actor：顾客
2. 前置条件：
   ① 顾客已进入商品列表。
   ② 目标商品处于可浏览状态。
3. 后置条件（成功保证）：
   系统展示目标商品的完整详情。
4. 触发事件：
   顾客选择一个商品。
5. 主成功路径：
   ① 顾客点击商品。
   ② 系统通过商品详情接口 API-S-IF2 查询商品信息。
   ③ 系统获取商品描述、图片、价格和库存状态。
   ④ 系统展示商品详情页面。
6. 扩展路径：
   2.a 异常场景：商品不存在。
   → 系统提示“商品不存在”并返回商品列表。
   2.b 异常场景：商品已下架。
   → 系统提示“商品已下架”且禁止购买。
   3.a 异常场景：部分非关键展示信息缺失。
   → 系统展示已有信息并隐藏缺失区域。

### UCG-001-UC003：加入购物车

1. Actor：顾客
2. 前置条件：
   ① 顾客已登录。
   ② 商品及所选SKU处于可售状态。
3. 后置条件（成功保证）：
   商品及购买数量被保存到顾客购物车。
4. 触发事件：
   顾客在商品详情页选择SKU和数量并点击“加入购物车”。
5. 主成功路径：
   ① 顾客选择SKU和购买数量。
   ② 系统校验商品状态、库存和限购规则。
   ③ 系统调用购物车写入接口 API-C-IF1。
   ④ 系统更新购物车商品数量和金额摘要。
   ⑤ 系统提示“已加入购物车”。
6. 扩展路径：
   2.a 异常场景：库存不足。
   → 系统提示当前可购买数量。
   2.b 异常场景：商品已下架。
   → 系统拒绝加入购物车。
   3.a 可选场景：购物车中已存在相同SKU。
   → 系统累加数量，但不得超过库存和限购上限。

### UCG-002-UC001：创建订单

1. Actor：顾客
2. 前置条件：
   ① 顾客已登录。
   ② 购物车中存在已选中的有效商品。
   ③ 顾客已提供有效收货地址。
3. 后置条件（成功保证）：
   系统生成状态为 WAIT_PAY 的订单并锁定相应库存。
4. 触发事件：
   顾客在结算页确认提交订单。
5. 主成功路径：
   ① 系统读取顾客选中的购物车商品。
   ② 系统校验价格、库存和促销有效性。
   ③ 顾客确认收货地址和订单金额。
   ④ 系统通过订单创建接口 API-O-IF1 创建订单。
   ⑤ 系统锁定库存并返回订单编号和待支付金额。
6. 扩展路径：
   2.a 异常场景：商品价格已变化。
   → 系统展示最新价格并要求顾客重新确认。
   2.b 异常场景：库存不足。
   → 系统标记缺货商品并阻止订单创建。
   4.a 异常场景：重复提交。
   → 系统根据幂等标识返回已创建的订单。

### UCG-002-UC002：支付订单

1. Actor：顾客、PaymentService
2. 前置条件：
   ① 订单状态为 WAIT_PAY。
   ② 订单未超过支付有效期。
   ③ PaymentService可用。
3. 后置条件（成功保证）：
   订单状态更新为 PAID，并记录支付流水。
4. 触发事件：
   顾客选择支付方式并确认支付。
5. 主成功路径：
   ① 顾客发起订单支付。
   ② 系统校验订单状态和应付金额。
   ③ 系统通过支付协议 PAYMENT-PAY-01 向PaymentService创建支付请求。
   ④ PaymentService完成支付并返回成功结果。
   ⑤ 系统校验支付结果并将订单更新为 PAID。
   ⑥ 系统向顾客展示支付成功页面。
6. 扩展路径：
   3.a 异常场景：PaymentService不可用。
   → 系统保留待支付状态并提示稍后重试。
   4.a 异常场景：顾客取消支付。
   → 系统返回订单详情，订单保持 WAIT_PAY。
   5.a 异常场景：支付结果重复通知。
   → 系统进行幂等处理，不重复更新订单。

### UCG-002-UC003：查看订单详情

1. Actor：顾客
2. 前置条件：
   ① 顾客已登录。
   ② 订单属于当前顾客。
3. 后置条件（成功保证）：
   系统展示订单的商品、金额、支付和履约信息。
4. 触发事件：
   顾客从订单列表选择一个订单。
5. 主成功路径：
   ① 顾客提交订单编号。
   ② 系统校验订单归属关系。
   ③ 系统通过订单详情接口 API-O-IF2 查询订单。
   ④ 系统组合订单商品、金额、支付和物流摘要。
   ⑤ 系统展示订单详情。
6. 扩展路径：
   2.a 异常场景：订单不属于当前顾客。
   → 系统拒绝访问并记录安全事件。
   3.a 异常场景：订单不存在。
   → 系统提示“订单不存在”。
   4.a 可选场景：订单尚未发货。
   → 系统不展示物流轨迹。

### UCG-003-UC001：商家发货

1. Actor：商家、LogisticsService
2. 前置条件：
   ① 商家已登录且拥有订单处理权限。
   ② 订单状态为 PAID。
   ③ 商品已完成出库准备。
3. 后置条件（成功保证）：
   订单状态更新为 SHIPPED，并保存物流单号。
4. 触发事件：
   商家填写承运商和物流单号后确认发货。
5. 主成功路径：
   ① 商家选择待发货订单。
   ② 系统校验订单状态和商家权限。
   ③ 系统调用发货接口 API-L-IF1 创建发货记录。
   ④ 系统向LogisticsService登记物流单。
   ⑤ 系统保存物流单号并将订单更新为 SHIPPED。
6. 扩展路径：
   2.a 异常场景：订单状态不是 PAID。
   → 系统拒绝发货。
   3.a 异常场景：物流单号格式错误。
   → 系统提示商家修正。
   4.a 异常场景：LogisticsService暂时不可用。
   → 系统保留待同步记录并进入重试队列。

### UCG-003-UC002：更新物流信息

1. Actor：LogisticsService
2. 前置条件：
   ① 商城已登记有效物流单号。
   ② LogisticsService已获得合法调用凭证。
3. 后置条件（成功保证）：
   商城保存最新物流节点并更新物流状态。
4. 触发事件：
   LogisticsService产生新的物流轨迹。
5. 主成功路径：
   ① LogisticsService通过物流事件协议 LOGI-EVT-01推送轨迹。
   ② 系统校验消息签名和物流单号。
   ③ 系统校验物流节点的时间顺序。
   ④ 系统保存新的物流节点。
   ⑤ 系统更新订单物流摘要。
6. 扩展路径：
   2.a 异常场景：签名校验失败。
   → 系统拒绝消息并记录安全告警。
   3.a 异常场景：收到重复物流节点。
   → 系统进行幂等处理。
   3.b 异常场景：物流节点时间早于已保存节点。
   → 系统保留原状态并将异常消息送入审核队列。

### UCG-003-UC003：查询物流信息

1. Actor：顾客、LogisticsService
2. 前置条件：
   ① 顾客已登录。
   ② 订单属于当前顾客且已发货。
3. 后置条件（成功保证）：
   系统展示最新物流状态和轨迹。
4. 触发事件：
   顾客在订单详情页点击“查看物流”。
5. 主成功路径：
   ① 顾客发起物流查询。
   ② 系统通过物流查询接口 API-L-IF2读取本地轨迹。
   ③ 当本地数据过期时，系统调用LogisticsService查询最新轨迹。
   ④ 系统按时间顺序整理物流节点。
   ⑤ 系统向顾客展示物流信息。
6. 扩展路径：
   2.a 异常场景：订单尚未发货。
   → 系统提示“商家尚未发货”。
   3.a 异常场景：外部物流服务查询失败。
   → 系统展示最近一次成功同步的数据并标记更新时间。
   4.a 可选场景：物流已签收。
   → 系统展示签收时间和签收状态。

### UCG-003-UC004：申请退款

1. Actor：顾客、PaymentService
2. 前置条件：
   ① 顾客已登录。
   ② 订单属于当前顾客且已支付。
   ③ 订单满足退款时限和状态规则。
3. 后置条件（成功保证）：
   系统生成退款申请并返回申请编号。
4. 触发事件：
   顾客在订单详情页选择退款原因并提交。
5. 主成功路径：
   ① 顾客选择退款商品、数量和原因。
   ② 系统校验订单和可退款金额。
   ③ 系统通过退款申请接口 API-R-IF1 创建退款单。
   ④ 系统向PaymentService提交退款请求。
   ⑤ 系统保存退款流水并展示处理状态。
6. 扩展路径：
   2.a 异常场景：超过退款期限。
   → 系统拒绝申请并说明原因。
   2.b 异常场景：申请金额超过可退款金额。
   → 系统提示顾客调整退款内容。
   4.a 异常场景：PaymentService暂时不可用。
   → 系统保存待处理退款单并异步重试。

### UCG-004-UC001：创建商品

1. Actor：商家
2. 前置条件：
   ① 商家已登录并通过经营资质审核。
   ② 商家拥有商品管理权限。
3. 后置条件（成功保证）：
   系统创建状态为 DRAFT 的商品并返回商品编号。
4. 触发事件：
   商家在商品管理页面点击“创建商品”。
5. 主成功路径：
   ① 商家发起商品创建。
   ② 系统校验商家身份和权限。
   ③ 系统调用商品创建接口 API-M-IF1。
   ④ 系统生成商品编号并创建空白草稿。
   ⑤ 系统进入商品信息编辑页面。
6. 扩展路径：
   2.a 异常场景：商家资质已失效。
   → 系统拒绝创建并提示重新认证。
   3.a 异常场景：重复提交。
   → 系统根据幂等标识返回已有草稿。

### UCG-004-UC002：填写商品信息

1. Actor：商家
2. 前置条件：
   ① 商品草稿存在且属于当前商家。
   ② 商家拥有编辑权限。
3. 后置条件（成功保证）：
   系统保存商品名称、描述、分类和图片。
4. 触发事件：
   商家编辑商品基本资料并保存。
5. 主成功路径：
   ① 商家填写商品名称和描述。
   ② 商家选择有效商品分类并上传图片。
   ③ 系统校验必填字段、文本长度和图片格式。
   ④ 系统调用商品信息维护接口 API-M-IF2 保存资料。
   ⑤ 系统提示保存成功。
6. 扩展路径：
   2.a 异常场景：分类不存在或已停用。
   → 系统要求商家重新选择分类。
   3.a 异常场景：图片格式或大小不符合要求。
   → 系统拒绝对应图片并显示限制条件。
   4.a 可选场景：商家暂未完成全部信息。
   → 系统允许保存草稿，但不允许发布。

### UCG-004-UC003：设置库存与价格

1. Actor：商家
2. 前置条件：
   ① 商品草稿存在。
   ② 商品已定义至少一个SKU。
3. 后置条件（成功保证）：
   系统保存每个SKU的库存和销售价格。
4. 触发事件：
   商家在商品编辑页提交库存和价格。
5. 主成功路径：
   ① 商家为每个SKU输入库存数量。
   ② 商家设置销售价格和可选原价。
   ③ 系统校验库存、价格和SKU唯一性。
   ④ 系统调用库存价格维护接口 API-M-IF3。
   ⑤ 系统保存设置并返回最新版本号。
6. 扩展路径：
   3.a 异常场景：库存为负数。
   → 系统拒绝保存并标记错误SKU。
   3.b 异常场景：销售价格不在允许范围。
   → 系统提示商家修正价格。
   4.a 异常场景：商品版本已被其他操作更新。
   → 系统提示数据冲突并要求重新加载。

### UCG-004-UC004：发布商品

1. Actor：商家
2. 前置条件：
   ① 商品处于 DRAFT 状态。
   ② 商品基本资料、SKU、库存和价格均已填写。
   ③ 商家经营资质有效。
3. 后置条件（成功保证）：
   商品状态更新为 ON_SALE，并可被顾客查询。
4. 触发事件：
   商家点击“发布商品”。
5. 主成功路径：
   ① 商家提交商品发布。
   ② 系统校验资料完整性、类目规则、库存和价格。
   ③ 系统调用商品发布接口 API-M-IF4。
   ④ 系统将商品状态更新为 ON_SALE。
   ⑤ 系统通知商品目录服务刷新可售商品索引。
   ⑥ 系统提示发布成功。
6. 扩展路径：
   2.a 异常场景：商品资料不完整。
   → 系统列出缺失信息并阻止发布。
   2.b 异常场景：商品内容违反类目规则。
   → 系统将商品送入人工审核。
   5.a 异常场景：商品目录索引刷新失败。
   → 系统记录待同步任务并自动重试。
