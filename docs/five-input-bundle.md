# 五类JSON文件识别、导入及节点复用

支持两种选择方式：递归扫描一个专用材料目录，或指定五份JSON的绝对路径。两者均按文件内容识别用途；文件名可以不同，RR/SR同名文件通过声明层级区分。识别和字面格式转换不调用LLM，不执行上传文件中的Skill或其他指令。

## 网页

- 新项目：点击“新建项目 → 从五类JSON文件夹／绝对路径新建”，填写项目名及目录，或逐项指定路径，预览后确认。
- 已有项目：“输入与导入 → 添加文件夹”选择文件夹，或“指定5份路径”填写服务所在电脑的目录／文件绝对路径。
- 预览逐行展示来源、用途和目标节点。勾选“采用已校验的部分字段和属性，其余仍由对应节点补齐”表示采用部分事实，不表示将整个节点标为完成。
- 替换已有成功产物须另勾选替换；旧版本保留。保存不会自动启动模型，运行中不覆盖在途结果。
- 目录监控默认自动识别：发现约定格式时，仅接收这些JSON，报告和Skill不送入转换模型。文件仍需两次稳定采样；项目执行中只收候选，空闲后登记来源。部分事实仍需显式确认。

本机目录指后端服务所在电脑。浏览器与服务不在同一电脑时，用“添加文件夹”上传文件，而不是提供浏览器电脑上的绝对路径。

## CLI

先启动工作台。Windows使用`scene.cmd`；源码运行时替换为`python scene.py`。

```bat
scene.cmd input-bundle --directory "C:\scene-input" --dry-run
scene.cmd create --name "同事材料验收" --input-dir "C:\scene-input" --adopt-partial --mode auto
```

已有项目可先预览再采用：

```bat
scene.cmd input-bundle --project PROJECT_ID --directory "C:\scene-input" --dry-run
scene.cmd input-bundle --project PROJECT_ID --directory "C:\scene-input" --adopt-partial
```

手动指定路径使用[示例清单](../examples/imports/five-input-paths.windows.json)。清单键固定为`RR`、`SR`、`function_tree`、`api_extraction`、`test`，值为真实JSON文件绝对路径。

```bat
scene.cmd input-bundle --file "C:\paths.json" --dry-run
scene.cmd create --name "指定路径验收" --input-manifest "C:\paths.json" --adopt-partial
```

可用`--expected-hash`绑定预览版本，文件变化后拒绝沿用旧预览；`--replace`只用于明确允许替换相关既有成功结果。新项目不需要替换参数。

## 格式及目标节点

| 文件内容 | 直接整理／复用 | 仍需执行 |
| --- | --- | --- |
| RR结构模型：`scope.model_level=RR`、`entities`、`relations` | `rr-use-cases`；本层已有异常分支发现 | RR/SR对应、融合SSD、实际交互定位 |
| SR结构模型：`scope.model_level=SR` | `sr-use-cases`；本层已有异常分支发现 | 以上对应与建模；异常逆向关注点及细化 |
| 功能树：`functions[].rrLayer/srLayer` | `business-entities-imports`中的实体及按用例保留的属性；为CRUD、字段映射和交互属性补全提供依据 | 未覆盖用例的实体信息；实际CRUD、实体依赖和业务依赖；LLM关注点识别 |
| 接口文件：`apis`中文字段、`services`及`software_units` | 按明确层级的API映射；`api-parameters-part-*`中的已声明请求部分 | 未提供层的独立接口、未知字段属性和成功／失败响应；不伪造完整响应 |
| 测试JSON：用例数组及`extensions` | `test-inventory`字面目录 | 测试用例对应、具体交互定位、关注点识别、具体场景与两层计分 |

测试文件自动登记为独立测试来源；不能作为已有需求异常E或正向生成G的输入。场景成功备选不计异常，无法明确分类的保留待确认，未覆盖用例显示未评测。

## 明确的复用边界

- 功能树中的业务效果不由HTTP方法或用例名称硬判C/R/U/D，具体交互和CRUD识别仍执行。
- 同一实体属性按原用例范围保存；浏览商品的状态约束不与创建商品的状态约束合成全局规则。没有字段信息的实体身份仍保留供CRUD使用。
- 接口层级来自明确声明，不按`/v1`、`/ms`等路径前缀判断。实现服务优先使用文件已确认的软件单元归属，歧义保留待定位。
- 功能树的接口属性缺少请求／响应方向时，不把`items[]`等名称猜成输出。仅在同层、同方法、同路径、已知字段位置唯一时补充。
- 不同地址不会因相同API编号而合并约束；这些分别保存，不开展需求一致性修复。
- 整数类型不自动推出大小、范围或位宽；可选缺省不算异常。未知默认值、数值阈值或响应行为不补造。
- `constraints[].error`、外部引文和原始错误码不作为G的正向约束。`missingConstraints`保留缺项，不能成为已明确的校验规则。
- 请求字段与成功、失败响应分别处理。接口文件只有输入参数时，节点仍需补抽允许材料中的响应；部分覆盖不会被工具直接当作完整产物。
- 全局业务关系、跨服务数据依赖、关注点识别和推荐仍依赖各自任务，不能仅凭这五份结构跳过。

## 冲突及来源

同内容副本按哈希去重；同用途出现多个不同版本时要求明确选择，不按时间或文件名静默取最新。AR、融合模型、Markdown报告及`SKILL.md`不作为本次五类自动输入。

原始文件逐字节保留；转换事实具有自己的来源ID、可读投影和原JSON属性位置。查看来源时可以打开同事原文件，不要求访问其引用但未提供的外部spec。采用记录显示哪些节点复用或合并了该文件；运行中的快照、历史结果及额度账本不会被导入重置。

当前实文件的识别规模为RR14用例、SR20用例，功能树14用例范围、13实体、185条按用例保留的属性记录和57个接口属性片段；接口文件20接口、56请求字段，无成功响应定义；测试JSON仅1用例、47个扩展分支，其中22个明确失败预期、20个成功备选、5个待确认。这些是输入及转换统计，不代表已经完成完整业务分析或生成最终指标。
