# SSD 三方比较与业务审核

新执行默认采用 `ssd-case-v1`。每个结构化用例独立完成三个阶段：建立 SSD 与三方结果、补充语义对应、比较与发布。原始文档继续使用现有抽取入口，得到 SSD、接口和实体后进入同一结果服务。全局关注点、全局幂等性和风险排序本轮不执行。

## 输入和挂载

导入整个 `输入文件` 目录，包含行为模型、功能树、API 提取结果、测试逆向文件，以及最初始的系统需求 spec 和功能设计 Markdown。Markdown 与 JSON 一起保存为不可变输入快照。中间来源继续保留，但“查看原文”优先显示初始 RR/SR 文档。未提供初始文件时明确提示缺少来源，不伪造引用。

IR/SR 同一次失败保留一条、优先 SR 定位；全部原出处都保留。IR 独有异常不会被删掉。字段约束按接口、方向和字段位置动态挂载，业务属性按实体关系挂载，非数据关注点按注册表结构规则挂载。G 不能读取 E/GT，测试不会因 G 没有识别某项而被裁掉。待确认来源在完成业务修正前不计分。

三个挂载目标为发送方、数据、接收方；操作、API、实体及 CRUD 是步骤属性。数据库无 HTTP API ID 的调用、本地 action、请求和返回均保留。

## 页面编辑

结果页可编辑步骤和三方结果、合并/拆分记录、修改挂载及匹配。保存生成新的修订，更新受影响的 G、匹配和指标。步骤或字段删除后，相关原记录保留为待重新挂载。解除 API 不会自动恢复旧字段。步骤 ID 不随显示名称、角色和排序变化。

机器原始版、历史修订和当前有效版本分别可查。自动运行只更新机器基线，人工修改和删除作为差量继续应用。原记录消失时显示修订冲突，不把它套到其他步骤。并发保存使用 `base_revision`，409 会保留页面草稿并要求刷新。

保存立即重算规则挂载、精确匹配及指标。修改场景条件或挂载后，相关旧语义判定失效并列入待比较；下次继续运行只复核未决场景对，自动复核形成独立修订，不改写机器原始版。没有可用模型时保留待比较范围，也可在页面人工判定。

点击任意记录“查看原文”打开页内弹窗，支持 Markdown 标题、列表、表格、代码块、章节大纲和引用行高亮。测试原出处与关联需求上下文分别展示。原文中的任意脚本不会执行。

## 离线审核

在比较页导出当前或全部用例的不一致项 HTML。文件内嵌有关原始文档，业务直接用浏览器打开即可查看出处、修正差异内容和匹配、填写审核意见。原文和 SSD 上下文只读。

“保存审核文件”会下载含修改的新 HTML；关闭后可重新打开继续审核。“导出修改”另存结构化 JSON。浏览器本地缓存不是唯一保存位置。

将审核 HTML 或 JSON 导回工作台，先查看修改和冲突，再选择用例应用。相同反馈不会重复应用，版本冲突不会覆盖当前结果。应用复用页面修订接口并重算，不会启动推荐任务。

## 指标与运行状态

令 `M=G−E`、`T=GT−E`：关注点漏报率为 `(1−|M∩T|/|T|)×100%`，生成有效率为 `|G∩GT|/|G|×100%`。场景诊断单独展示，项目按分子分母求和。空分母显示不适用；未挂载、待确认及未完成项单列。

完整重复运行复用验证过的任务输出。单用例失败不阻塞其他用例。历史 mock 输入按其原任务契约回放；新流程 mock 验证显式设置 `workflow_mode: "ssd"`。原协议和历史报告不原地改写。

注册表文件中已迁移到全局的四个旧交互幂等键，在运行解释时统一停用；原用户 JSON 不被改写，也不会再因首次读取创建无意义的注册表修订事件。

## 接口

以下路径均位于 `/api/projects/{project_id}`：

| 接口 | 用途 |
|---|---|
| `GET ssd-results` | 当前用例版本与项目指标 |
| `GET results/{case_id}/editor?revision=original或版本号` | 当前/历史/机器原始结果 |
| `POST results/{case_id}/revisions` | 提交 `base_revision`、编辑后的 `bundle`、可选 `reason` |
| `GET results/{case_id}/revisions` | 修订历史 |
| `POST ssd-review/export` | 可选 `case_ids`、`record_ids`，返回离线 HTML |
| `POST ssd-review/preview` | `content` 为审核 HTML 或 JSON，返回差异/冲突 |
| `POST ssd-review/apply` | `content` 与所选 `case_ids`，应用已预览反馈 |

`import-case-result` 同时接受新的 `ssd-case-v1` 与旧 `scene-case-analysis-v1`。旧提交保留原三方结果和匹配，不用新的脚本 G 覆盖原 G。独立脚本使用 `.cac/skills/scene-case-analysis/scripts/case_analysis.py build`。

## 本地验证

运行 `make check` 和 `make frontend-build`。新增回归覆盖五用例、原文追溯、IR/SR 去重、请求/响应分离、API 改绑、步骤修订、历史版本、并发冲突、语义判定失效、离线 HTML 保存重开及反馈幂等。离线测试不代表客户模型网关或原生 Windows 已验收。
