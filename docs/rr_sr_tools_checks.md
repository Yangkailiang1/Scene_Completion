# 可迁移的方法与每轮检查接口

正常查询的逻辑结果按 [logical-query-results-v1](rr_sr_logical_query_data_policy.md) 追溯。模型校验要求实际 read 交换、同层正向原文、字段成员和未知结构标记；来源检查独立逐行区分 explicit/query_semantics，核实引句与返回映射。未标记或未独立确认的推导不能通过。SSD JSON 保留 derived_data，图中显示推导及结构待确认；不会自动升级历史模型或增加调用。跨领域测试覆盖异常分支引用、越界/跨层、非读取、伪造类型、独立检查未确认、输出结构与图形标记。

交付对象是 Skills、输入/输出协议和 tools。项目样例只用于验证方法；不得在工具中硬编码商城用例、服务名称、接口编号、预期分母或达标场景。其他项目可提供自己的 RR/SR 文档和用例定位种子，支持不共享编号前缀、一对多拆分、多父级复用及内外资源服务。

用户当前授权少量代表用例流程验证，使用`--use-case-id <原编号>`明确范围（可重复）。正常模型原包及完整检查器基线保留原始Skill/模型身份；代表评估C另存`assessment_checker_scenarios.json`，不改写完整C。源文、实际抽取代码/指令、分类和章节分配改变仍阻止复用；仅报告口径文字改变不要求再次抽取已经独立核实的C。`--comparison-verification final-review`省去重复全量比较，最终实际独立效果审查仍须完成，不冒充双批复核。

`--source-quality-gate structural`只允许显式代表范围。来源审查完整性、引句/版本及真实执行证明仍核验，否定结论原样保留在JSON、Markdown和工作簿输入质量诊断中，作为样例质量发现；不以它们反复重抽项目输入。真实正常来源、SSD/挂载链条、架构确认和图形/集合校验仍阻断不合法输入。默认`strict`继续要求来源质量通过。方法流程通过不等于样例文档或模型质量认证。

## 实际执行后端

默认ECNU，用户授权后可切换`--agent-runtime luna-subprocess --config luna.config.example.json`。本地子进程固定`gpt-6-luna`，批量high、最终审查max，最多三个并发，输入只有当前语义包；明确禁用工具、文件和网络访问，使用临时只读会话。保存事件、JSON、stderr、线程、命令与哈希，工具检查成功退出、完整消息、批次绑定、没有工具越界执行及保存语义与原始JSON一致。原始输出不被字段标准化改写，标准化只作用于后续读取。额度用尽时保留实际错误，停止重复请求，未发起包保持deferred，不冒充完成。

已有版本有效且明确授权的ECNU批次可以续用，不能重标为Luna或把新的Luna结果标为ecnu-max。运行报告列出各阶段实际请求模型；本地CLI未公开底层路由模型时明确保持空值。离线复验需要携带native-runs中的原始证据，缺失、篡改、错误线程或未完成输出均阻止正式验收。调用失败不算未匹配。

## 每轮检查

`scene-pipeline` 结束时自动保存 `run_checks.json` 和 `run_checks.md`，包括未完成、源文审查不通过或架构确认待定的轮次。也可随时执行：

```bash
python .cac/tools/scene_completion.py check-interaction-run \
  --output-dir <round-dir> \
  --rr-spec-document <rr-original.md> \
  --sr-spec-document <sr-original.md>
```

显式文档参数会重新核对原文版本；省略时检查保存的输入快照。输出 `status=pending|blocked|passed`、`structurally_valid`、`formally_accepted`、各阶段批次状态及 `issues`（编码、阶段、批次 ID、具体原因）。用户已撤销漏报率门槛；指标只如实报告。结构完整且可离线重建仅使 structurally_valid=true；passed/formally_accepted 还要求实际回归、续跑、Luna 审查及当前 acceptance.json。代表用例范围另存，完整原文基线不删减。合计漏报率单独报告。退出码 0 表示正式检查通过，2 表示未完成或阻断。

| 检查 | tools 如何执行 | 阻断条件 |
|---|---|---|
| 输入与执行版本 | 原文/输入哈希、协议、阶段依赖版本、实际模型请求证据 | 原文改动、过期包、错误/缺失模型证据 |
| 批次完整性 | 校验输入哈希、全部批次及逐对比较清单 | 缺结果、重复/未知 ID、被截断或无效 JSON |
| 架构与 SSD | 校验同层交换、真实生命线、消息嵌套和层级拆分 | 错层、无锚点、循环、未确认新增调用或模型缺口 |
| 正常模型完整性 | ecnu-max只读原始正常流程及模型，逐行/逐交互/逐场景/逐字段/逐契约核实；tools独立核对职责映射与证据绑定 | 漏调用、返回误作请求、本地伪自调用、异常冒充普通可选、AR混入、无据契约、字段缺少交换证据、职责映射分歧 |
| 全部关注点 | 完整注册、正向操作/关系路由及每个挂载的生成结果 | 注册缺失、候选删除、无效挂载或异常旁路 |
| 独立 C 来源 | ecnu-max 源文审查包，只读取原文和 C | 正常流程误算异常、条件未拆分、跨操作契约、错误引用或原文异常遗漏 |
| 完整结果重建 | 全流程离线重建输入包、G/C、系统/设计分别匹配、指标、全部推荐的测试采纳 | 人工修改、集合漂移、匹配复核分歧、错误推荐/采纳分母 |

结构校验不能代替语义判断。源文审查保留模型判断、原文引句、行号和问题；最终实效审查仍核实这些判断是否正确。匹配不使用字符串相似度或错误码，生成器不经过 LLM 适用性筛选。

正常来源检查还独立盘点物理资源操作：`resource_operation_reviews`逐个数据库核实正向SR中的调用，工具检查原调用方、同层实际资源端点或显式`physical_resource_id`封装及原文行。业务入口→服务不能替代服务→资源，`implementation_references`不能替代SSD消息。原文操作无对应交换报告`source_resource_call_omitted`；来源没有绑定到该交换报告`source_resource_call_without_anchor`。仅架构声明而本用例无正向调用的资源不补造交互。原文是否表达实际调用仍由来源语义判断负责，不宣称工具能单凭字段名解析任意文档。

来源审计输出无效时可执行 `diagnose-normal-source-audit --output-dir <实验目录>`：工具重新核对原包/来源版本并保留实际验证错误，仅提供该原包的同层正向原句位置和数据字段规则。不能将格式错误当作模型遗漏或填写通过；worker结束后加`--prepare-retry`保存原始失败及诊断反馈，再续跑原阶段。运行中的worker禁止写入重试反馈。真正缺陷仍需原文依据的模型重抽和完整来源再检查。

Luna 结构化来源审计的引句字段只能选择本包原文行或其连续片段；数据盘点引句进一步绑定到所选的具体原文行，候选不包含抽取模型或审查反馈中的改写文字。判断仍由模型给出，数据缺口仍可返回空映射。工具随后检查记录与实际交换位置，不能用本包另一条原句代替正确出处。共享谓词不重复补写为原文，完整原句可保留多个并列操作。

显式选择 `--source-review-file` 和 `--source-finding-id` 重抽时，仅传入已核实的指定语义缺陷及必要结构检查。同一用例中未经核实的审计意见不自动变为修复指令；重抽后完整来源审计仍须重新通过。模型缺陷和审计判断错误分开保存：前者触发原文重抽，后者通过 `retry-normal-source-audit` 保持模型不变重新判断，二者均不是正式验收证明。

## 正常交互模型来源与遗漏检查

`model_origin_checks.json`逐条核对同层正常/普通可选来源，参与者列表、另一层步骤或异常回退不能单独证明请求。不能识别的文档流程标题产生明确证据缺口。它不能单独证明语义完整性，因此另有`interaction-model-audit`：只输入原文、正向抽取Skill及正常模型，不读取C/G/测试；每个正向流程行、已建交换、正常/可选场景必须恰好检查一次，保留缺失调用及原文引句。请求须有对应同层来源锚点；数据库读写按明确SR正文服务化，AR实现不扩成SR。正确处理的异常仍不能算普通可选成功。

每包保存原模型内容哈希和审查规则版本，全部包完整且通过后才能生成；`model_source_audit.json`与原始批次共同进入离线重建和最终效果审查。审查模型可能误判，工具完整性/引文校验不能代替最终语义复核。

同一“备选流程”标题可同时包含普通可选和异常；没有“可选”字样的分支不自动拒绝或接受。只有对应同层、原包内容绑定的完整语义审查通过，才可解除这类来源待核实状态；来源检查同时保存审查哈希。引句必须是原文单行连续片段，不能拼接流程、改写、替换换行或加省略号。错误返回标明具体行/交互/场景与原文位置，全部失败尝试保留。

```bash
python .cac/tools/scene_completion.py repair-generator-model-origins --output-dir <round-dir> --config <config.json>
```

该命令在没有G的草稿轮次工作；保留原始模型及完整源文审查反馈，仅让ecnu-max从原包重抽被拒绝的正常模型，不手写遗漏调用或异常。语义审查反馈必须完整且当前有效；已有G则新建可追溯轮次，修复后仍需重新审查并核对架构确认。生成器的异常具体化与全部挂载候选不经过此审查筛选。

资源别名归一只接受被引用原文中的字面表标识；保留命名空间、内部/外部属性、来源文档和原始名称。没有此证据时不去掉任意后缀或合并相似名称，不虚构资源接口路径。

结构抽取失败可先执行：

```bash
python .cac/tools/scene_completion.py diagnose-generator-model --output-dir <round-dir>
# 当前 worker 完成后，给后续重试留下具体诊断；不修改图或已完成结果：
python .cac/tools/scene_completion.py diagnose-generator-model --output-dir <round-dir> --prepare-retry
```

`normal_model_diagnostics.json`记录失败批次、原始尝试及内容哈希、具体角色/交互和结构错误。它指出缺失 SR 入口、逻辑边界与接口混淆、错误父调用或非法功能分类；候选父交互仅表示结构上可能，模型仍须从原文判断。重试反馈保存在新的尝试文件，原始失败结果不变。输入只有原包、正常模型尝试和来源索引，不读取 C/G/测试、不补写调用或异常，也不将诊断当作通过证明。过期输入绑定直接拒绝。

明确写为“异常场景/异常流程”的原文行不能由语义审查解除为普通可选；即使 HTTP 200 或状态保持合法也不改变原文分类。未标注的备选仍需独立语义核实。工具逐行检查引用，拒绝包含换行或跨行拼接的引句，包括解释被拒绝场景的负向证据。

正常模型来源另外识别“触发事件/Triggering event”中的发起行为：部分文档的基本流程从系统处理开始，真实请求在触发段，不能因此漏建或误拒绝交互。触发段仍逐行区分请求、返回、本地处理和上下文；标题及纯前置条件不作为请求证据。这是正常模型独立规则，不改变检查器原始异常基线。

已通过格式检查的审查若声称某请求被覆盖，而关联交换没有该请求行的来源锚点，原始审查决定保持不变，工具另列`tool_findings`并令整体`passed=false`。该完整但未通过的审查可供原文重抽定位；不能把工具判定与模型声称覆盖混为已通过证据。每轮检查分别执行正常模型和固定C完整性核验，一个角色阻断不能掩盖另一角色的异常或修改。

## C 草稿修复与冻结

遗漏审查另存实际异常分支的`failure_source_refs/failure_evidence_quote`；泛指分支展开同时保存同操作`contract_source_refs`。正常校验、纯前置条件或普通可选不能单独构成遗漏。`issues`只列缺陷，不允许四项通过同时报告问题；正向解释不得误当拒绝依据。

抽取全部完成后，编排器生成 `interaction-checker-audit` 包。每包保存对应 C 内容哈希及原始章节，逐项检查异常依据、原子性、操作绑定、引用和遗漏。全部包完整且无问题后才写入固定 `existing_scenarios.json`。

有问题的草稿可执行：

```bash
python .cac/tools/scene_completion.py repair-checker-source-audit \
  --output-dir <round-dir> --config <ecnu-config.json> --env-file .env
```

工具先核对完整审查集合与当前 C 哈希，以独立文件保留每次错误原始结果、所有审查依据和完整反馈，然后让 ecnu-max 只读取原始包及审查问题重新抽取；旧 C 内容不作为 previous_output 输入。不会手工改写场景或静默修改分母；修复完成仍返回待审状态，必须重新运行编排器准备并执行新的完整源文审查。已冻结 C 禁止原地修补，须建有修订记录的新基线。

跨轮 `--checker-input` 导入只读快照必须包含原文核实记录、完整直接抽取和源文审查执行证明。来源、分类、抽取规则变化则拒绝复用；不冒充新模型执行。

## 阶段版本与复用

每轮记录完整 tools/Skills 版本；每个语义包另外记录其实际函数、模型配置解析、传输及响应解析依赖版本，并将真实 Skill 文本及输入数据纳入哈希。模型抽取接收 scene-extract、scene-ssd 与多级输入规范；生成接收 scene-generate；检查/源文审查接收 scene-check，匹配接收 scenario-match，推荐接收 scene-recommend。

正常模型来源审计未完成或未通过时，编排入口将参与者阶段标为 `awaiting_normal_source_audit`，不调用下游参与者分析。检查器仍独立执行。只有完整来源审计通过后，参与者阶段才读取其中已核实的普通可选调用证据；推迟状态不计作完成、未匹配或正式验收。

RR 字段审计区分明确传输契约与内部成功状态。本层成功保证中明确“返回申请编号”等数据，可以由已存在交换的原文返回描述或独立审计通过的正向契约支持；仅写内部状态成功变化不能据此推断响应字段。异常回退不能供给正向数据证据，前后置条件不能创建调用或职责。重复 RR 请求展开同一 SR 流程时，合法契约可复用原 SR 引用；工具仍核实每个交换的父级、对象、时点与来源，不凭文字重复删除候选。

正式来源审计包要求 `source_data_reviews` 独立逐原文行盘点传输数据，再对应真实同层交换及实际字段。它与已有字段的证据审查互补：既查字段泄漏，也查空字段数组掩盖原文明示输入/返回遗漏。缺失映射产生 `source_transfer_data_omitted`，字段有名但该交换没有原文锚点产生 `source_data_mapping_without_anchor`；均保持原文引句并阻止生成。引用、层级、字段ID及批次由tools检查，数据语义仍由源文审计判断；此功能不读取检查器或测试，不直接修改模型。
独立测试异常提取接收 test-scenario-extract，并将 assessment.py 解析器指纹保存在 input.test_parser_version。推荐包包含关联原文片段及每个候选的同层原文用例章节；建议补充位置必须在该范围内，不凭文档名或引用编号推断证据。

改变检查器来源绑定规则会使 C 包过期；修改生成挂载会改变 G 输入及后续比较集合。修改报表样式不会强迫重新执行无关语义抽取，但必须按当前完整版本重新编排、检查和重建报表。模型、思考配置或实际输入变化不能借标签改写旧缓存。

## 实际验证与效果审查

完整流程结束后执行：

```bash
python .cac/tools/scene_completion.py validate-interaction-run --output-dir <round-dir>
python .cac/tools/scene_completion.py prepare-interaction-review --output-dir <round-dir>
# 实际 gpt-6-luna/max 审查完成并保存原始结论后：
python .cac/tools/scene_completion.py evaluate-generator --output-dir <round-dir>
python .cac/tools/scene_completion.py check-interaction-run --output-dir <round-dir>
```

validate-interaction-run 实际运行本仓库完整 pytest，保存命令、退出码、JUnit 计数、原始日志及代码/测试版本；失败、错误和跳过数均须为零。随后对全部语义包运行真实续跑 worker，禁止调用模型，以 socket 拒绝哨兵阻止网络访问，记录实际尝试数，要求每包 cached 且所有输入/结果文件和离线重建指标前后相同。acceptance_checks.json 引用原始记录哈希；工具不接受人工填写的 tests_passed 布尔值。该验证不替代漏报门槛和实效审查。

prepare-interaction-review 输出 effect_review_materials.json，绑定原始 RR/SR/测试输入、SSD、全部挂载、G/C、源文审查、匹配、指标、推荐、采纳、章节诊断和批次原始结果。实际子 Agent 审查须留下 effect_review_raw.json：materials_hash、unresolved_findings 和 areas；areas 逐项包含 area、passed、reason、evidence_files，覆盖 ssd_only_generation、layer_isolation、mandatory_concerns、source_atomicity、exception_identity、metric_denominators、recommendation_adoption、remaining_gaps。effect_review.json 记录真实 agent_id、model=gpt-6-luna、reasoning_effort=max、result_hash、materials_hash、raw_review_hash、passed 和 unresolved_findings。脚本验证材料/原始审查/范围绑定；这是可审计的执行记录，不是对模型身份的密码学证明。

baseline_review.json 还须保存 source_audit_hash，绑定源文审查的完整输入、结果及执行证明；证明变化即拒绝导入。只有当前 acceptance.json 与工具重新评估完全一致，check-interaction-run 才能报告正式通过。回归失败、漏报超限、审查未完成或材料改变均阻止该状态。

编排器在目标项目的完整来源审查通过后，自动依据实际结果生成baseline_review.json（不接受调用方填写通过布尔值）。批次数量取当前输入全集，不硬编码样例数量；此来源审查记录与最终Luna实效审查是两项独立证据。

本轮尚未满足验收门槛。历史旁路结果、旧分母和局部试包均不作为新方法达标证明。

当前评估规则为`rr-sr-one-to-one-workflow-v5`，取代历史`rr-sr-one-to-one-concern-units-v4`的覆盖达标门槛。RR建立本层正向来源的五类逻辑服务职责及真实SR映射；RR、SR独立抽取并分别与本层G一一分配，指标如实报告、不设置漏报阈值。推荐沿实际层级映射对同一实际原因合并，保留各层关注点标签和原成员；不同原因不合并。测试不区分RR/SR，原始异常按交互、单一因果关注点及条件拆分，泛指异常允许框架推导，但标为framework_derived并保存引句和推导依据。test_all逐对判断后一一分配，采纳率分母为去重推荐单元数，明示与推导贡献分列，空分母null。回归、来源/匹配复核、续跑、离线重建与真实Luna效果审查仍必需；可明确采用final-review复核策略以省去重复全量比较，不能伪称双批比较。早期来源证明保持原样，不改写旧包来冒充当前版本。

已发现的来源问题不能因为新一次模型审计通过就视为修好。对尚未冻结的同一 C 草稿，可指定完整历史审计中的被拒绝包：

```bash
python .cac/tools/scene_completion.py repair-checker-source-audit \
  --output-dir <round-dir> \
  --historical-audit-manifest <round-dir>/batches/interaction-checker-audit/manifest_history/<hash>.json \
  --checker-batch-id <rejected-checker-batch-id> --config <config.json>
```

工具要求保存在本轮的完整历史审计、未改动的输入/结果哈希、实际ecnu-max证明、明确拒绝原因及与当前C完全相同的内容哈希；仅让模型重抽被拒绝的原包，保留旧草稿和证据，不手工改写C。冻结后仍禁止原地修复。重抽后须重新准备并完成当前来源审计，历史拒绝证据本身不能当作新版通过证明。

## 指定源文审查驱动重抽

`repair-generator-model-origins`可使用`--source-review-file`和逐项`--source-finding-id`，把已实际完成的正常模型源文预核问题交给ecnu-max从原始模型包重抽。工具验证当前模型/源文哈希、原包及实际模型、精确原文引句、输入章节范围和交换ID。审查文件只能是正常模型源文预核，不能包含效果评估作为修复依据；未指定项不自动改写。原结果及反馈保留到attempts，G存在时拒绝修改正常模型。

这允许先修复已明确的源文抽取问题；不完整、过期或拒绝的全量来源审计仍然阻断后续生成及指标，修复后必须重新完整运行。不能以局部预核或手写passed标记宣告验收。

显式选择源文发现时，重抽范围始终限定其所属用例；即使另一个用例的完整来源审计失败，也不会顺带删除或重抽该包。未选择的问题仍阻断全量验收。资源审查要求正常模型的`components`结构，不能把另一阶段的`nodes`结构误认为“没有数据库”。

如果实际复核发现错误来自审计判断而非正常模型，使用单独入口：

```bash
python .cac/tools/scene_completion.py retry-normal-source-audit \
  --output-dir <round-dir> --source-review-file <source-review.json> \
  --source-finding-id <audit-finding-id> --config <config.json>
```

发现必须明确`target=source_audit`并绑定当前实际审计包、模型和逐字原文。工具保留旧审计及反馈，重新运行原审计包，并验证正常模型没有变化。审计错误不能用于正常模型重抽；单项重审仍须通过原校验器，不等于全量通过。

原文中确有的数据若遗漏在交换的请求/返回引用中，保留原文数据判断并输出`rr_field_source_not_bound`，不得当作来源通过。审查给出的职责映射与模型不同，即使模型回答`correctly_modeled=true`，tools也输出`rr_role_mapping_disagrees`并阻断。此类结果是完整审查中的模型问题，保存到tool_findings用于源文重抽；无效引用、未知ID、未完成的必审清单仍拒绝整个批次。返回/展示数据属于同一SR交换的返回消息，不能为补映射虚构新的调用。

来源预审若提供`input_hash`、原始包及结果文件哈希，工具逐项核对；审计预审使用对应的`audit_*`字段。结果被重新执行或包已变化时，旧发现不能继续用于修复。独立来源拒绝记录形成续跑边界：被拒绝的输出及更早尝试不能从执行证据恢复为新结果，必须实际重新抽取或重审。连接失败后的不可变原始输出仍可在当前执行证明和语义校验均通过时恢复，两种情况分别记录。

`diagnose-normal-source-audit`还定位重复数据项、资源操作的实际组件ID/原文引句，以及缺少判断标志或标志与缺陷清单矛盾的具体记录。反馈只指出结构错误和原文位置，不替模型决定语义、填字段或删除问题。一个原文数据在多个真实交互上传输时保留全部映射，不通过重复数据清单条目或重命名数据绕过唯一性检查。

数据来源清单不完整时，诊断还输出应有／实际行数、遗漏行、重复行、未知行及遗漏行的原文。没有传输数据的行也须单独说明并返回空数据项；工具不会替模型判断该行是否有传输数据，不改写失败原始输出。这项检查适用于所有项目的正常交互抽取。

Luna 来源检查可设置 `native_structured_audit=true`：工具由现有输出协议生成 JSON Schema，传给实际 CLI 的 `--output-schema`，保留 schema 文件及哈希，并核验原始输出结构。Schema 约束必填数组、布尔判断、枚举和问题清单结构，不替模型决定分类或覆盖关系；引用正确性及真实缺陷仍由原来源校验器检查。失败不能静默回退为通过。

传输数据和资源操作的引句均绑定到所选原始行；来自另一行的字面原句也不能作为该行引句。数据来源清单的条数须与原始行数一致，重复／未知行仍由完整性校验拒绝。资源调用方、操作和缺失映射保持模型独立判断，结构约束不会把不存在的调用方或交换填成有效记录。

返回字段关联不要求模型返回描述逐字复述原文。若正向成功保证引用已绑定同一交换，来源审查独立确认本层正常返回行，且原始传输清单逐字段映射到该真实返回交换，工具可核实这条证据链。内部操作、错层、请求方向、未绑定保证或错误字段均不能走此关联；不会由工具增加字段或修改原始审查判断。跨领域回归覆盖上述正反例。

普通可选分支可以在同一请求上返回，无需为了返回内容新增一次请求。跨行分支正文的返回字段须同时关联：本层明确可选的原文、独立核验通过的可选场景、该正文的真实返回清单及既有交换锚点。未核验、被拒绝、错层、非可选、缺少锚点或字段映射及异常分支均拒绝。该检查不把取消行为变成异常，不改变检查器分母或关注点挂载。

五类服务判别规则统一保存在 `.cac/skills/scene-extract/references/service_classification.md`。正常抽取包将文件全文放入 `extraction_skills`，来源检查包继承同一文本；普通校验不自动成为分析生成，任意外呼不自动成为发布生效。文件变化使生成输入及其来源检查缓存过期，检查器基线独立：没有修改原文、分类注册或检查抽取规则时，仍可通过完整原始执行／来源审查证明导入固定 C。测试使用不同领域的用例验证规则确实进入两个角色的输入，并验证规则变化不会改写 C。

首个长批次启动前保存实际运行清单及输入／运行配置，每个阶段准备后先记录未完成状态，再执行和汇总。`diagnose-generator-model`遇到组件名称与引用不一致时提供当前引用的原始行和已分配原文中非异常的字面名称位置；这些位置不是自动选择的替代引用，也不授权新增调用。诊断验证使用原始输出的副本，反馈和哈希仍绑定不可变失败原包，避免校验过程的引用规范化改写执行证据。

资源来源检查同时记录 `caller_source_name`（原文正向 SR 行中的字面执行方）和 `caller_component_id`。执行方未进入模型时，ID 留空、交换列表留空，由工具产生阻断项 `resource_caller_not_modeled`；不能让公共入口冒充正文明确命名的服务，也不能编造 ID 或调用。已经建模但没有资源交换时单列 `source_resource_call_omitted`。正式新包要求字面调用方，原文角色缺失与调用遗漏分别保留证据；审计只能提出补全，不修改模型或授权未确认组件。旧包不会冒充新协议来源通过。

原文明示返回业务集合时，可由同一真实交换上、正向契约明确组成该集合的字段共同表示；来源审计逐项给出这些实际字段及语义依据。无需为了审计另造一个重复包装字段。未知成员、其他交换或不存在的字段仍拒绝；集合缺少实际字段映射时仍报告遗漏。数据名称/字段组合的语义由来源审计判定，工具校验字段存在、方向、层级和原文锚点。

正常模型重抽、来源重审和重试诊断准备均检查该阶段的全部 worker 状态，包括指定批次与分片 worker。任意实际 worker 仍在运行时拒绝改包，避免修复与批量执行同时改动输入或原始证据。

SSD 导出保存 Mermaid 与 SVG，并通过 `ssd_diagram_files.json` 关联原始用例 ID 和文件。SVG 使用已校验的真实消息顺序、分支条件、请求／逐层返回和 SR 资源服务生命线，不推导新调用。文件名对跨项目编号、路径字符及 Windows 保留名做安全转换，原始编号仍保留在图和索引中。图形导出不替代来源或覆盖验收。

# 批次执行诊断

`check-interaction-run` 的每阶段 `execution_progress` 区分有效输出、输出无效、执行失败、延后未执行和待执行/返回，并在 Markdown 中列出额度限制影响的当前批次。只统计当前 manifest ID；最新逐批记录用于解释尚未完成的工作，已经有效收集的结果取代旧额度失败。worker 自报完成不能替代结果校验，进度不授予来源通过或正式验收。失败和未执行批次不能视为未匹配。提供方原始错误文本留在私有执行记录，不复制到公开诊断。



## 明确授权的局部交互链验证

仅本次测试可用 `--use-case-id <ID> --exchange-local-id <RR本地ID> --exchange-local-id <SR本地ID>`。工具拒绝未知、重复、缺父调用、无RR或SR，以及冒称全范围的选择。完整正常模型与SSD保留，生成使用所选链的全部有效挂载；原文C分母保留，漏报不能解释为整用例质量判断。默认不加范围参数仍全量运行。

测试按代表业务范围选择原始相关记录，不按RR/SR筛选；相关可选异常保留，普通正常记录不能被推导为异常。跨层推荐等价判定最多16对一个批次，逐对校验全部ID、证据和必要条件，遗漏、重复和非传递判定仍阻断。分包只减少启动开销，不减少语义比较集合。

参与者原文引句可以启用本地结构输出约束，从原始用例和架构行中选择连续字面片段；不能从抽取模型描述生成引句。工具仍校验所引行、层级和实际参与者状态，空可选引句不意味着可以省略必需证据。错误定位包含组件ID、引句字段和原文行号，不人工修正语义结论。


## 可迁移的离线结果检查

`export-interaction-snapshot` 首先调用完整运行的离线复验，再生成不含私有配置/执行缓存的结果快照。`rebuild-interaction-snapshot` 不调用模型，重建真实SSD和所选范围全部挂载，验证每个比较对（包括未匹配决定）均存在、没有重复或越界，并重新计算一一覆盖和测试采纳、核对原指标/结果哈希后导出报告。重建明确标记 `execution_evidence_verified=false`，不继承正式验收状态；原始执行证明仍只能用完整运行的 `check-interaction-run`、`validate-interaction-run` 和 `evaluate-generator` 核验。
