# 测试Markdown导入、用例对应与推荐前后指标

本次修订保留 scene-workflow-v4，增加两个可独立审核的任务，不改写历史报告。

## 输入与类型

- 带表头的测试表接受原始非空编号，不要求TEST-/SUP-前缀。真正重复编号或表格必填缺项会定位到文件及行号，创建失败不会留下半个项目。
- 恢复用例文档支持用例标题、主成功路径和`EXT: exception / alternative_success / undetermined`分支，保留原`SC@...`编号及引用。用例总览不再误判为测试表。
- 不在上述格式内的非空Markdown允许导入，运行时由独立测试整理任务读取原文。支持任意排版不表示可以推断原文没有写出的事实；不能确定的内容列为待确认。
- 原始文件、测试用例编号、场景编号和坐标保留。`exception/异常`才进入确定GT；正常、可选、未标明类型和待确认保留查看但不计分。统计中的“收敛”标记不覆盖分支类型。

## 真实任务依赖

1. `test-inventory / scene-test-inventory`：仅从测试文件形成测试用例、场景、类型及证据。已知格式使用确定解析，未知格式调用模型，不默认为空测试集。
2. `test-case-align / scene-test-case-align`：读取独立测试用例自身的目标、参与者、前置条件和正常流程，以及RR/SR用例目录和已确认用例组。不传测试异常列表、G、E、匹配和推荐结果。明示需求编号精确对应时使用规则；其他情况由模型依据双方业务描述判断。
3. confirmed对应的测试才进入该需求用例。pending/unmatched及理由在待确认项和“测试场景→测试与需求用例对应”中展示，不静默丢弃，也不冒充全部验证完成。
4. `test-concerns`根据该用例融合SSD，把异常定位到实际交互、发送方/操作项/数据字段/接收方及关注点，形成GT_c。此层仍是稳定标识规则匹配。
5. `test-ground-truth`在独立测试及正常约束范围内细化GT_s，再执行场景匹配。GT不读取G/E来补答案，推荐排序不读取GT。

新产物：`test-inventory.json/.md`、`test-case-align.json/.md`，每用例`test_catalogues/用例ID.json`保留作用域内原始测试记录。不能确定测试用例对应时，正向场景及缺失分析仍可交付；关联GT不被算成空集。共享对应任务传输失败时需恢复该任务，不能把失败当作无测试。

## 推荐前后使用同一GT

场景层新增`recommendation_comparison`，同时保存或只读展示：

| 阶段 | 候选集合 | GT命中率（推荐采纳率口径） | 误报率 |
|---|---|---|---|
| 推荐前 | 全部缺失M | `|M∩GT|/|M|×100%` | `|M−GT|/|GT|×100%` |
| 推荐后 | 算法筛选Q，Q⊆M | `|Q∩GT|/|Q|×100%` | `|Q−GT|/|GT|×100%` |

两者共用冻结GT及保存的完整对应候选，在各自候选子集内执行一一分配，不由前端或排名算法重判语义。空分母“不适用”；未启用/未评测不能显示为0。GT分母下误报率可能超过100%。实际人工采纳率与GT命中率分开。

原始、扩展测试来源各自评测；项目汇总先合并分子分母，不平均百分比。历史版本Q不属于当前M时显示“版本不一致，待重算”，不混算且不覆盖旧文件。
