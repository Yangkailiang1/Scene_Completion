# 执行控制与新版关注点设置

网页项目运行时显示“暂停任务”和“停止任务”，暂停/停止后使用“继续运行”恢复。暂停不再派发新的模型请求，等待在途请求完成后保存；停止终止当前项目工作进程，保留成功产物、审核记录和检查点，未决请求的用量仍按未知处理，不自动重发。用户暂停/停止后，后台自动恢复不能越过明确继续。

CLI与网页共用接口：

```bat
scene.cmd execution-control --project PROJECT_ID --action pause
scene.cmd execution-control --project PROJECT_ID --action stop
scene.cmd execution-control --project PROJECT_ID --action resume
```

支持`--dry-run`。服务端`POST /api/projects/{id}/execution-control`接受`action=pause|stop|resume`，审核包不允许执行控制。

设置页分为“交互级关注点”与“全局业务依赖级关注点”。人类身份/权限和Service之间的关系与单个Service内部区分；Service内部采用第一层基础数据及业务实体属性、第二层业务实体C/R/U/D、第三层展示/分析生成/发布生效、第四层数据库/LLM。输入输出及多种CRUD引用同一稳定定义时不因展示路径重复计分。

用户于2026-11-03确认新增三个独立定义：输入数据有效性（引用资源存在/有效）、数据库特殊字符处理、存储数据有效性；停用资源消耗。数据合法性及旧变更业务约束保持停用，枚举属于数据范围。特殊字符本身不必然非法，输入引用有效性不由字段含Id或integer类型推断，存储规则不等同于接口参数规则。识别仍由模型结合证据完成，新增注册不自动变成G。

旧项目当前设置一次性迁移并保存版本、原始自定义内容和审计；冻结的定义、已有G/E/GT、报告和分数不覆盖。后续重跑受影响识别和下游后才采用新定义。模式库对应增加三项规则违反模式，不因设置页浏览重跑模型；历史模式停用资源消耗，项目后续人工修改仍保留版本。
