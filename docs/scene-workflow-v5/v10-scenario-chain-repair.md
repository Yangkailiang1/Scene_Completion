# v10：关注点到场景链路修复

本版以a42dfad为基线，保持scene-workflow-v5、四项正式指标公式及原始材料不变。定位与评测标识更新为`two-level-concern-scenario-v10-evidenced-scenario-expansion`；v9存档保留为历史，不原地修改指标。

下述S4职责确认是用户另行明确的业务材料修订，区别于工具修复；已更新仓库mini样例的正向描述，不修改客户Downloads输入或冻结历史报告。

## 修复内容

- 场景已经定位后，绑定校验不再把正向引用当成异常描述重新寻找失败服务。外部调用的可用性候选不会因为引用JSON中出现上游服务名称而移到另一请求。
- 已识别且有明确适用证据的调用方身份、数据隔离、授权和业务属性规则能够展开条件级场景；不推断Token、签名、过期时间或响应码。正常规则索引漏项不再直接丢弃该明确规则。
- 单一操作序列项与整次操作名称完全相同时，共用一个关注点定位。调用方枚举违例可关联认证、范围等多个关注点，但同一独立失败只生成一次。
- 独立测试中，仅当同一实际请求、同一测试只注入一个字面枚举违例，且该字段已被本通道独立识别为调用方条件时合并重复场景。保留全部来源、原始ID及关注点关联；不同字段、值、调用或未知关系不自动合并。
- 数据库非字段唯一性在G/E/GT中使用统一存储作用域。接口字段和存储字段继续隔离。已识别的存储Schema字段使用自身明确规则展开；有据的长度和数值区间拆成上下界，不从接口字段自动推断数据库约束。
- 条件式跨字段业务规则不能提交成两个普通字段范围识别项；校验拒绝后由有限修复预算重新识别，工具不读取另一通道结果补答案。
- 正常规则支持返回字段任务，分片、上下文和传输Schema不再排除return。返回规则归响应发送服务，限于输出数据检查；普通成功枚举与当前操作明确的成功值分别保留。
- 正常规则只输出不超过500字符的原文条件子句，工具验证引用包含该子句，不再用整行JSON覆盖条件，减少重复材料与错误规则混合。
- 保留正常规则上下文中的action与validates。明示的本地业务检查即使没有重复列出报文字段，仍可识别实体业务规则；唯一且有据的入站业务操作可提供实体关联，不新增CRUD行或全局操作计数。多个候选不猜测。
- 逆向识别读取同一测试的完整触发、预期及备注，定位明确的失败自检；不借用相邻测试。复合伪字段、把跨字段业务条件当普通范围等明确契约错误交给有限修复，不把它们悄悄作为空GT成功结果。
- 正向材料明确要求同键不同内容拒绝时，全局幂等场景必须独立覆盖该模式；不能以同内容重复执行代替。无键机制依据时不强制补造该模式。

## 指标展示

正式漏报率与生成有效率仍为关注点层。用例指标接口增加`scenario_diagnostic`，单独展示基于已保存场景集合及判断的缺失诊断、未命中清单和三方冲突。

若G与GT对应、G又被E覆盖，但GT没有对应E，诊断显示冲突，不通过传递关系自动补计命中。空分母显示不适用，无评测显示未评测。场景诊断不是自动修订后的新正式成绩。

## 验证与使用

离线回归覆盖错误重定位、调用方机制、跨字段分类、作用域、同失败多关注点、输出固定值、幂等子模式和分母边界。五个mini用例可在冻结识别产物上重放正向工具，输出单独诊断：

```sh
python tools/replay_scenario_chain.py --project PROJECT_DIRECTORY --output OUTSIDE_PROJECT/replay.json
```

该命令无模型调用，不修改项目。识别产物与当前规范不兼容时记录`recognition_repairs_required`，不把无效识别自动补回确定G。报告中的新场景尚未做完整语义比较，不产生新的正式指标。

ecnu-max返回字段定向实测已通过，实际返回模型为deepseek-flash；验证了成功响应status=PUBLISHED被整理为数据范围规则。初次小样包括被拒绝请求共计15,689 Token；后续S4职责识别、独立GT及单对比较另用9次请求、76,762 Token，合计12次请求、92,451 Token，无未知用量。原始包、响应及账本快照仅留本机。

本版仅更新受影响的任务语义版本。系统组成、接口与SSD等未变化的公共任务不因界面或文件变化整体失效；旧的场景定位与比较缓存不能冒充v10结果。完整五例新指标需在独立运行中重新识别受影响项及比较，不覆盖旧报告。本轮不制作Windows包。
