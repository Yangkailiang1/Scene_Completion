# 确定性关注点与结果范围

规则版本：`two-level-concern-scenario-v9-mandatory-rules-global-idempotency`。

## 确定性识别

用户确认的策略由程序执行，不再以模型是否提交作为必要条件：

| 实际步骤 | G中的规则 |
| --- | --- |
| 人类Actor发起真实请求 | 身份认证、访问授权各一个绑定 |
| 已确认的外部Service真实调用 | 接收方服务可用性一个绑定 |
| 明示的资源存在性检查，且已确认本次R/U/D业务效果 | 对应CRUD资源存在性，绑定实际检查职责 |
| 当前操作的明确service-id访问隔离要求 | 操作上的服务间数据隔离 |
| 当前用例、实际操作及字段共同适用的跨属性业务条件 | 通用业务实体属性约束，保持关系整体 |

原文仅证明参与者或业务效果时，不能声称它明确约定了认证机制、故障码或响应方式。结果保留`policy_id`、`identification`和来源；策略不读取E、GT、匹配答案。E和GT不获得G的默认项。

同一完整绑定重复出现时合并来源。401与403可能是不同失败场景，但身份、权限各自的同一关注点绑定不能重复显示和计数。不同字段、方向、实际调用不因名称相同而合并。

URL包含`productId`本身不证明检查职责。发布商品的样例具有已确认更新效果，且数据库自检明确核对存在性，因此绑定该自检；不能把该约束复制到每条上游请求。已有文件的自检未单列CRUD时，仅在本次同一接收方有唯一、已确认的委托业务效果时使用其分类；歧义不猜测。

## 全局幂等性

只对全局C/U/D按“用例＋业务实体＋操作”强制识别一次。R不强制。重复提交、同键不同内容等场景在该全局绑定下展开。

E、GT先独立分流：明确幂等失败不能通过交互分流校验，归属未知时待确认，不改挂交互。交互识别也拒绝把旧幂等关注点计入确定集合，保留排除原因和原始来源。请求头缺失仍可以是字段异常，不自动等于幂等失败。

历史报告保持原计分和版本，不能直接把旧交互ID改成全局ID后声称新版评测已完成。网页标记历史报告；新版需独立绑定全局业务操作并重算。

v8到v9仅改变确定性G策略归属的两份已审阅Skill按完整SHA-256列为语义响应兼容对；不是忽略提示词变更。输入、Schema语义、模型所有者、端点及指导仍须一致，原始响应仍须重新校验定位、证据与字段覆盖。其他旧提示词（包括旧交互幂等版本）不在兼容表，不能复用为新版结果。

## 三个结果入口

- **用例结果**：用例选择、交互对照、本用例指标、用例图表、测试场景、风险推荐、用例诊断。
- **全局业务分析**：全局异常对照、业务依赖、全局指标和推荐。无用例选择器。
- **项目指标**：项目总指标与交互级汇总。无用例选择器。

`GET /api/projects/{project}/results/{case}/metrics`只读取当前用例评测，携带测试来源和接口范围；不会取全项目百分比冒充本例。保留项目汇总与全局接口。空分母、不完整结果和历史版本分别说明。
