# 独立worker启动修复（2026-11-04）

## 已复现的问题

在 `310adc4` 的源码上，以隔离解释器从 `/tmp` 分别直接运行 `project_worker.py --help` 和 `manager_worker.py --help`，两者均返回退出码1及 `ModuleNotFoundError: No module named 'scene_completion'`。原因是入口先导入项目模块、再设置路径；不是接口ID、模型参数、调度器缓存或业务材料错误。

前版的模型／工作流回归在父测试进程内导入了包，无法覆盖这个独立解释器入口，前版Windows原生验收也未执行。本轮不据主网页可用宣称worker可用。

## 修复与验证

- 两个worker都先依据自身文件定位 `src`，然后导入对应运行模块。
- 新增四项子进程回归：两个入口在中文及空格的迁移目录中，以 `-I -S` 关闭用户环境、site与PYTHONPATH影响，加载指定的最小运行模块；两个真实运行模块在隔离子进程中从无关目录执行 `--help`。
- 发布包原生检查增加实际嵌入式Python独立启动两个worker，不能仅测试父网页。交叉打包时另外用构建机解释器检查包内源码入口，记录为宿主验证，不冒充Windows原生结果。
- 修复不改变项目存储、任务ID、Schema、提示词、模型预算及业务缓存身份，不清空已完成产物或额度账本。

本轮不调用付费模型。具体完整回归数量和发布提交写入本次 `delivery-validation.json`；Windows原生与客户网关仍待客户验证。
