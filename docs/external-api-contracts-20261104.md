# 外部Service接口与引用契约修复验收

2026-11-04，本次只执行离线回归，不调用客户网关或付费模型，不改动额度账本、原始材料或旧报告。

## 本次行为

- 系统组成确定外部Service身份后，RR/SR分别建立系统接口和外部接口任务；文档来源与服务边界是两个维度，不按地址前缀分类。
- `rr-external-api-map`、`sr-external-api-map`独立抽取本层外部接口，汇总为`external-api-map`和`external-api-index`。外部接口使用独立机器命名空间，保留原编号和来源层级。
- 外部参数任务同样按接口拆分，汇总为`external-api-parameters`。包含请求、成功响应、各失败响应及接口级认证/签名要求；正式结果并入总表，并参与实际外部调用的属性补全及后续分析。
- 明确的Mermaid方法、路径和接收方可以由工具恢复遗漏项；保留原行证据。不确定归属、残缺路径和抽象调用不能被工具猜成HTTP接口。
- 取片保留Mermaid参与者别名、相关返回和认证说明。原文直接声明SA+RS256_PSS等要求时原样保存协议/算法，不推导头名称、密钥、时限或响应行为。
- `interface_constraints`保存接口整体要求，与字段类型、长度、范围等约束分开；参数Schema缺失不等于接口没有约束。节点预览、接口总表和Markdown导出可查看这些要求。
- 未启用索引时不挂载lookup_evidence，source_refs保持来源ID/行号/逐字引文对象；启用索引时使用本任务ID表。引用格式与未知ID分别报告，拒绝记录保留JSON字段路径。
- 诊断返回程序VERSION.json/Git版本及本次引用模式、文档来源和投影哈希。source_commit不作为文档source_id，不更改历史文档身份。
- 没有外部接口的项目不产生外部接口模型调用；已有系统接口完整输入仍可复用。新任务不把无接口、缺Schema或未完成状态伪装为完整接口。
