# API映射身份修复验收（2026-11-04）

本轮针对客户报告的 `id=local-rr-s001`、`declared_id=pending]` 导致 `RR::pending]` 与 `RR::local-rr-s001` 不一致。前一版只验证了无占位元数据的合并路径，未覆盖这个失败分支，不能据前版通过结果宣称此问题已经解决。

## 最终处理

- 机器身份唯一来自 `id`。`declared_id` 仅是原始标识元数据，合法文档标识可以与内部机器ID不同，不能再用它重命名接口。
- 模型侧API映射Schema不提供 `declared_id`、`source_layer`、`interface_scope`；Skill要求输出有效接口ID或稳定本地ID，工具负责一次性添加来源／边界命名空间。
- 提交与缓存读取拒绝身份占位符，拒绝重复ID和层级冲突，诊断保留结构化 `identity_error`、字段路径与被拒绝候选。
- 映射、目录共用限定身份工具；API目录显式依赖聚合映射，在参数展开前核对完整身份集合，错配归为API目录校验失败，不再等到顶层字典查找抛KeyError。
- 旧的非法自动审核缓存不再反复盖过新候选；保留历史，按当前契约校验后定向恢复。有效缓存不因本次代码排版或程序版本变化整体失效。
