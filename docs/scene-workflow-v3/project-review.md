# 项目级关注点与待确认项

工作台的四个入口是工作区、待确认项、关注点设置、用量与费用。配置、导出和执行模式统一收在“更多操作”。管理页使用整个工作区；普通阅读默认84%工作区和16%任务导航，可拖动或专注阅读。

## 待确认项

待确认项按来源区分正向建模、原文已有异常E和独立测试GT，不因文字相同合并不同通道。可以按用例、来源、状态及关键词筛选。展示具体交互、对象/字段、原文行号和来源节点。

业务可选择是异常（选择启用的具体关注点）、不是异常/跳过或待补材料，并填写依据。审核不自动调用模型、不改写既有报告；意见持久化到来源节点，后续在该节点重新执行时使用。不把E或测试答案传播到G。模型阻断问题和技术失败也统一展示，但需回来源节点处理，不将技术错误直接判作业务异常。

`pending_decisions.json`保留最新判定和全部历史，含条目快照、定义哈希、来源节点、审核版本及时间。判定绑定当前候选ID，候选内容变化后不静默沿用旧判断。

## 项目定义版本

每个项目初始化时冻结默认模板，后续模板升级不自动改变已有项目。定义包含稳定ID、名称、说明、层级、功能/技术分组、父关注点、适用操作和适用依据。名称可编辑；内置数据检查使用稳定ID识别，重命名不会破坏类型/范围等检查。

新增、修改、停用和恢复生成新版本。删除采用停用，历史定义仍可解释旧产物。存在启用子项时须先调整继承，禁止循环。数据、人类和服务关系关注点使用对应命名空间，五种功能分类及数据库/LLM身份沿用当前框架。

发布新定义不自动重新评测。下一轮只因定义及实际依赖变化重算分析节点，组成、API等无关抽取不因定义编辑强制重做。执行使用的定义被冻结；定义变化后重算前，将旧缺失报告、任务状态和清单归档到`run/report_versions`，可在历史定义页下载对应报告。未知具体规则不会因定义存在而变成确定异常。

## 接口

- `GET/PUT /api/projects/{id}/registry`：查看/发布项目定义。写入携带expected_hash；GET可指定version。返回历史版本及关联报告。
- `GET /api/projects/{id}/pending`：分页筛选（status、case、channel、search、offset、limit）。首次增量索引读取当前有效产物，后续复用派生索引。
- `POST /api/projects/{id}/pending/{item_id}`：提交choice、concern_key、note及当前revision。不触发模型请求。

项目注册表通过ContextVar在执行和请求范围内隔离，线程任务继承本轮冻结上下文；没有进程级全局字典替换。注册表内容哈希进入分析缓存身份。修改不能影响同时执行的其他项目。
