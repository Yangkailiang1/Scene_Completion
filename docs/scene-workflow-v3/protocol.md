# scene-workflow-v3

本版以融合SSD中的具体交互为分析和比较单位。两类交互为人类Actor↔Service、Service↔Service；RR/SR保留来源、步骤展开和显示视图，不能用来源层级不同直接拒绝同一交互的匹配。只有在已确认展开关系中、端点和方向相同的重复视图才归为同一次调用；真实下游调用不能合并。关注点继续使用interaction-concerns-v3注册表，不新增设备规则。

比较先排除不同用例/交互、已知不同作用域或字段位置，以及不同的明确API参数标识（HTTP请求头名称不区分大小写）。中文说明、未知字段及可能的语义对应继续交给模型。原文同交互的宽泛参数非法覆盖规则优先保留。模型每片最多判断32个candidate_pairs，不再输出左右数组的笛卡尔积；程序合并为完整比较矩阵。单对缓存绑定完整左右输入、比较用途、节点、指导版本和提示规则，改变分片边界不会重复请求已验证候选对。

生成G的source_status固定为framework_inferred，original_branch_id为null，coverage_kind为exact。每项仍须提交非空的正常规则推导依据。Actor/Service及操作关注点以对象为匹配单元；其中提到的参数只是触发条件，不把该参数注释当作独立数据异常field。接口数据及存储字段异常继续保留字段单元并按明确规则校验。E/GT来源及原分支覆盖语义不受此规范化影响。

同一用例中多次实际请求分别展开调用链。SR的可复用流程可以引用相同证据，但每次执行使用独立消息ID、父请求及返回关系，不能因为端点、接口或操作名称相同而合并。首次进入页面和随后筛选分别展开；只有同一次执行的RR/SR视图对齐后合并计数。结构工具不自行复制调用消息；发生次数有歧义时先确认。

## 独立输入和产物

- 共享组成、RR/SR目录、API映射、接口索引、原文异常分支可并行。用例对应就绪后动态展开用例任务，无关API任务不会阻塞完整SSD。
- API索引给出接口ID、名称、原文范围；每接口子任务只输出索引指定接口，单独校验、缓存和保存，再合并API参数表。未知属性不猜测。
- 建模器从正向描述、能力表、API表和预定义关注点形成G，不读取E、测试GT或比较结果。
- existing-branches保留原分支；existing-bind绑定具体交互并标明confirmed/pending/not_this_case；existing-extract细化为E，保留original_branch_id、canonical_interaction_id、interaction_type、coverage_kind、source_status、derivation。
- 测试GT由测试spec、融合SSD和明确正常约束独立整理。宽泛测试参数异常按已知约束展开，只有可判定细项进入GT，未知规则进入pending，不向G取答案。

当前JSON Schema见schemas目录；稳定机器字段与来源引用同样保留。新任务Skill：原文异常分支抽取、异常交互绑定。逆向细化沿用独立Skill入口，普通核对仍在各任务内部。

## 覆盖和指标

E的exact项仍按对象、操作、原因及必要条件完整对应；同一交互的input_parameters原分支可覆盖多个请求参数细项，包括必填缺失和违反类型、格式、枚举、范围等已知约束。不覆盖返回数据、其他交互或存储Schema约束。原分支和细化子项同时保留用于追溯，生成细项的覆盖只计一次。

M={g∈G | 没有适用E覆盖g}。无匹配记录不覆盖指定实例不存在。GT按字段和具体失败原因去重，GT↔G仍语义一一对应；GT↔E支持上述宽泛覆盖。

- 缺失异常漏报率：(1−|M∩(GT−E)|/|GT−E|)×100%。
- 生成有效率：|G∩GT|/|G|×100%。
- GT明示／框架推导分别列出；没有测试GT显示未评测，空分母不适用。推荐未启用，不生成Q。

## 会话、执行状态与接口

节点会话持久化在事件数据库的messages表，恢复点保存在checkpoints表；不作为其他节点或角色的共享记忆。普通指导在下一次模型调用注入，标记已接收／已生效。当前HTTP不会被假装即时修改，新指导尚未应用时提交不会晋升为正式产物。

ask_user记录问题、原文依据和待决定事项，当前节点awaiting_answer，独立节点继续。回答后恢复会话、累计调用计数和修复轮次。到探索预算时只允许提交或提问；每个已回答问题增加一次恢复调用额度，默认最多3次澄清，累计计数不清零，避免回答后无法继续或无限提问。完成后指导可重新执行该节点；成功结果与受影响下游按输入和指导版本失效，无关任务复用。

新增接口：

- GET/POST `/api/projects/{id}/conversation`：读取节点会话或发送指导（task_key、text）。
- POST `/api/projects/{id}/answer`：task_key、question_id、text，回答后恢复。
- POST `/api/projects/{id}/rerun-node`：按最新指导重做；产物仍需验证。
- graph补充planned、input_summary、artifacts、question、guidance_revision、retry_at、retry_count；流程预告不计进度。
- SSE增加conversation_message、guidance_applied、question_asked、rate_limit_wait。模型正文与工具参数仍增量持久化，正式产物只接受完整已验证结果。

429共享降并发并冷却，遵守Retry-After，缺省2/4/8秒，单请求最多3次自动重试；额度、认证、超时、截断分别记录。超时不自动重POST。完成节点立即导出；旧失效产物移入previous_artifacts，不通过当前产物区发布。

## 升级

旧协议运行记录保持不变。旧项目点击继续运行会创建新版项目并复制源文及本地配置，不复用旧异常/计分缓存。原项目、失败和审核历史继续可查。正文/原有文档不修改。本轮只交付网页，不创建Windows发布Tag或离线包。

## 模型传输等待

连接／首响应使用timeout_seconds；stream_idle_timeout_seconds默认300、stream_total_timeout_seconds默认900。流式每次读取上限取无数据等待与剩余总时限的较小值。项目显式配置优先，界面可调整。超时记录phase、timeout_kind、elapsed_seconds、first_event_seconds、last_event_age_seconds、partial_content_bytes与incomplete_tools，不包含请求头/密钥或模型隐私推理文本。输入文档以完整原行号文本呈现，Schema只通过提交工具提供；可查虚拟原文件保留。

## 按任务／角色选择模型

本地模型配置可设置`role_models`（modeler/checker）、优先级更高的`task_models`，以及按模型名称索引的`model_profiles`。Profile仅接受生成参数、时限及额度账本，不能改写凭证、端点或材料通道。切换模型必须显式设置独立`token_budget_ledger`，避免多个约1M额度共用账本。所有模型继续共享请求门控、限流冷却、暂停及修复上限；实际模型记录在节点事件和产物执行证据中。关闭思考仅用于支持该选项的模型，不能给GLM/Kimi等思考专用模型强行关闭。

## 索引与模型侧精简契约

Markdown一次建立章节树（source-index工具），以原始source_id、行号及内容hash保存。原始文档不删除。用户确认的“非抽取权威”历史段和关联实现OpenAPI/AR附录标记default_input=false，不进入默认RR/SR建模。

组成、API映射和RR/SR用例目录先经独立document-context工具取片。目录只用标题、清单及元数据，API映射只用接口身份/方法/路径/归属，SSD再按已确认source_ranges读取这组用例正文。大文档无索引时等待确认，不退回整份；4KB以内小输入可整体提供，并在审计中明确范围。接口参数仍按接口索引单独取片，未知接口关联不以全量参数表兜底。

模型传输使用indexed-evidence-v1：source_refs是当前上下文给定的evidence_id，完整引用由程序从受控输入恢复。SSD双方使用component_id；case_id、层内序号、返回类别及唯一的嵌套调用结构由工具整理。refinements引用消息ID，区别于用例编号；程序恢复对外标准rr_sr_links。只有已有消息可进入展开闭包，不新增消息或改变其方向/端点。多个可能父调用进入待确认。

SSD不重复生成接口data_type/required/default；本次字段和位置先保存，接口属性由独立参数任务与交互属性工具关联，额外业务约束仍保留。SVG由程序绘制。测试操作投影只允许将操作名称字面片段带出，证据整行中的异常条件/预期响应不得进入能力表或G。

用量接口`GET /api/projects/{id}/usage?format=html|json`按节点提供全部历史请求、已报告输入/输出token、其中思考、未知usage、请求累计耗时和原文范围。输出已含思考，不重复相加；并行请求累计时间不是项目墙钟时间；未发送的暂停/预算阻断不算实际调用。费用不由token预留反推。

目录存在概要与详情重复项时，必须选择包含正式用例编号记录的详情章节；source-index给出原始详情边界，SSD再取其中正向流程。中文“备选流程/替代流程”与扩展路径一样进入独立已有异常通道，不进入正向建模。

`ssd-context`工具保存本组RR/SR正向正文与相关组件身份子集。RR/SR消息证据ID区分前缀，不能互相替代。`model_contexts`保存实际发给模型的精简业务上下文（不含凭证）；用量报告点击任务ID可查看最新上下文。关注点适用状态、继承路径、服务功能和技术身份由工具校验整理，模型只补充语义依据。

生成器只接收已适用且有具体规则的语义匹配行，不携带整张审核矩阵。字段、查询资源存在性及基础可用性由工具生成；没有额外语义规则时该任务直接保存工具结果，不发起模型请求。模型候选的交互—对象—关注点受当前适用列表约束。完整矩阵及待确认项仍保留在审核产物中。

缺失/评测比较先用已确认的宽泛参数覆盖，以及相同正常规则ID和完整失败单元的严格一致性判定。仅未决候选进入按交互、最多8×8的小批次语义核验；完整对应矩阵仍保存，不能跳过其他语义候选。模型侧格式错误和后处理错误均保留候选用于定向修复，不丢弃已有合法部分后重新生成。

结构整理忽略请求中误填的reply_to传输提示，由实际端点和顺序独立确定父调用；重复SR返回只在存在唯一同向同端点RR直接对应时整理归属。多个同等直接对应仍需确认。每项整理写入执行证据normalizations，原始模型候选保留；不新增消息、不改方向、端点或业务数据。
